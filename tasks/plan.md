# Windows Harness 実装計画

## 目的と前提
Windowsの英語チャットで音声入力・読み上げ・筆跡注釈を扱い、原本を残しながら教材案を理解しやすく比較・承認できるようにする。利用者から前回提案の設計・実装指示を受けた。Androidは今回考慮しない。

## 設計契約
- 元の録音、元の筆跡、注釈の対象となる英文、実際に送信するPNG、文字起こし結果と訂正文を区別する。録音は既存の30秒上限を維持する。
- 添付は独立ファイル。Progressには参照・説明のみを追加し、旧JSONをserde defaultで読める。原本を自動削除しない。ファイル長とハッシュを検査し、保存失敗時に保存済みと表示しない。
- 手書き文字認識とは別に英文注釈面を用意する。英文と描画座標を固定し、送信前の画像プレビューを提供する。取消線は削除の承認ではない。
- 認識は自動送信しない。元の会話・下書きへだけ結果を反映し、途中で変更された下書きを上書きしない。Codexへ送る媒体を利用者に明示する。
- 会話コンテキストの選択はWordWeaveに残す。過去の原本を保存していても毎回すべて送信しない。教材化は選択した往復の固定版を根拠とする。
- 比較は構造（項目・例文・言い換え）で整列し、変更箇所を文字単位で強調。理由と引用はAIが返した情報と照合し、未取得や利用者編集後に推測で補わない。根拠は隣に表示し、引用一致部分だけ強調する。
- 新規・追加・訂正・削除の承認境界と復習記録保護を維持する。生成結果がそのまま教材ファイルを書き換えることはない。
- 実行前に意図を保存し、応答を検査前にも回収可能な形で保存する。未完了で再起動した処理は結果不明。通信切断・待機終了をサーバー中断確認にしない。再保存と再生成を区別し、自動再生成しない。
- ChatGPT認証のapp-serverだけを使い、既存CLI設定・Volta/PATH探索・返却モデル/effortのみの表示を保持する。
- 二つの既存保存ファイルの更新について保存途中の失敗を成功扱いしない。根拠・媒体を含むバックアップ手段を用意する。

## 構造・規約
`src/`はRust本体、`src/app/`はWindows egui画面、`tests/codex_process.rs`は実APIを呼ばない子プロセス試験。新規の純粋ロジックはlibモジュールに分離し、画面を巨大化させない。既存の`Result<T, String>`とserde形式を踏襲する。

```rust
// 保存が成功するまで、表示中の確定データを置き換えない。
storage.save(&next)?;
*progress = next;
```

## 検証
基本コマンド：`cargo test --all-targets --locked`、`cargo build --release --locked --bin wordweave5`。
各スライスで失敗するテストを先に追加し、既存記録の互換性、壊れた添付、範囲外座標、根拠不一致、同一操作の再反映、保存失敗を検査する。テストは専用一時フォルダーを用い、実学習データを変更しない。GUIは可能な環境で実測し、マイク・ペン実機・実Codexの未検証は明記する。

## 境界
常に：既存データを保持、境界検査、変更ごとの試験、作業記録更新。
別途確認：破壊的移行、外部サービス導入、利用者データへの破壊的操作。
禁止：APIキーへの切替、未取得値の補完表示、無断教材登録、検証していない成功の主張。

## リスク
CLIの音声/画像能力はテキスト生成成功から推測しない。未対応なら明示して文字入力は維持する。
旧版は追加フィールドを保持しない可能性があるため、更新後データを旧版で再保存しない。
OS電源断・音声認識品質・Windowsペンの物理操作は単体テストでは実証できない。

タスクの進捗は `tasks/todo.md` に記録する。
