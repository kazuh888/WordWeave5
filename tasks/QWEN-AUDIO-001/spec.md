# QWEN-AUDIO-001 外部仕様

状態：U0独立レビュー合格・親採用済み。2026-10-02。実装の確定契約である。実API・音声評価品質の合格を意味しない。

## 目的・根拠・境界

Windows上の独立した小規模アプリで、選択した読み上げWAVと英文をQwenへ送り、日本語の練習用フィードバックを得る。CodexからもローカルMCP経由で同じ操作を開始できる。将来WordWeave5へ再利用できる評価機能とするが、今回WordWeave5への組込みは行わない。

要求元は親の利用者要求伝達と [sources.md](sources.md) である。次のR-IDは要求追跡用であり、利用者の発言を直接引用したものではない。

| 要求ID | 要求元の内容 |

| R01 | 利用者承認済み：慎重に設計・実装する独立Windows音声評価アプリ。後でWordWeave5へ再利用 |
| R02 | 利用者指定：`qwen3.8-omni-flash`、Japan (Tokyo)で有効化・キー作成済み。キーは会話で扱わない |

## ローカルMCP契約

JSON-RPC/STDIO。stdoutはMCPプロトコル専用であり、診断に秘密/録音/英文/評価本文を出さない。MCP設定を利用者環境へ自動登録しない。

| 受入ID | 要求 | 操作と出力 |
| --- | --- | --- |
| QA-AC-018 | R06/R07/P02 | `start_reading_session({"reference_text":"The sun is bright."})` は参照文をP02で検証しGUIへ事前入力する。音声/キー/送信先/ファイルパスを引数に受け取らない。未知フィールド・型違いは入力エラー。成功は推測不能な`session_id`と`status:"awaiting_user"`を返し、操作待ちやAPI完了を同期的に待たない。GUI起動失敗は明示エラーとなり進行中枠を残さない |
| QA-AC-019 | R06/P03 | `get_reading_result({"session_id":"…"})` は対象の現在状態のみ返す。副作用/再送/GUI起動なし。`completed`のみ構造化`result`を返す。`failed`は秘密を含まない`error:{code,message}`、`cancelled`は結果なし。繰返し取得しても終端結果は同じであり読取りで消費しない |
| QA-AC-020 | R06/R07 | `cancel_reading_session({"session_id":"…"})` はQA-AC-012を適用する。既に終端ならその状態を変更せず返す。取消しと完了が競合した場合は先に確定した終端状態を返し、その後変更しない |
| QA-AC-021 | R06/P03 | 進行中に追加開始すると`busy`。未知/削除済み/別プロセス起動時のIDは`session_not_found`。終端最新16件を保持し、次の終端確定で最古一件を削除する。プロセス終了でセッション/結果は全て失われる。プロセス再起動で自動復元/再送しない |

## 構造化結果の提案形式（P05）

UTF-8 JSONオブジェクト。未知フィールドを拒否し、自然文は命令として実行しない。以下の構造を満たすJSONのみをGUI/MCPで評価結果とする。全文64KiB以下、文字数はUnicode scalar数である。

```json
{
  "assessment": "assessed",
  "heard_text": "The sun is bright.",
  "summary": "文全体を滑らかに読めている。",
  "strengths": ["語尾まで読み上げている。"],
  "improvements": [
    {
      "reference_excerpt": "The sun is bright.",
      "observation": "brightを少し強くすると意味が伝わりやすい。",
      "practice": "brightを強め、前後の語は軽く読んで練習する。"
    }
  ],
  "unassessable_reason": null
}
```

`assessment`は`assessed`/`unassessable`のみ。`summary`は空白だけでない1～2,000文字、`strengths`は0～8件の空白だけでない各1～1,000文字、`improvements`は0～8件で各フィールド1～1,000文字（空白だけ不可）。`reference_excerpt`は確認した参照英文の部分文字列でなければ形式不正とする。`assessed`では`heard_text`が空白だけでない1～10,000文字、`unassessable_reason:null`を必須とする。`unassessable`では`heard_text:null`、空白だけでない1～2,000文字の理由と空の良い点/改善配列を必須とする。部分的にしか聞き取れず安全な評価ができない場合も`unassessable`とし、聞き取れなかった発話を参照文から補わない。中間の`limited`状態は今回設けない。

構造検証は内容の真実性を証明しない。発音・強弱・リズムを実際に聞き分けた質、意味の妥当性、評価不能の適切さは実機受入対象である。生AIテキストの表示は今回要求しない。
