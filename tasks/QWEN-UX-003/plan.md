# QWEN-UX-003 計画：音読評価の3段階一画面

2026-10-03。状態：P1。親がAstraの [外部仕様](spec.md) 全文と [設計](design.md) を承認したとの引継ぎに基づき、P0を精緻化した。仕様本文の提出時表記と親承認の根拠を区別する。利用者承認済み3段階UIの再承認ラウンドは不要である。計画担当は本書と [todo.md](todo.md) のみを所有する。独立レビュー/実装/検証の完了は本更新から推定しない。

## 完了境界と根拠

音読ダイアログを①音声の準備、②送信内容の確認、③評価結果の確認へ再構成し、状態に対応した説明と操作を各段階に置く。実装・焦点回帰・本体全体test/release・独立レビュー・合成fixtureによる表示確認までを開発完了境界とする。実マイク・実API・実音声の評価精度と利用者による最終画面受入は別の未検証項目である。

規約、開発7役、KPI、導入済み `agent-skills:planning-and-task-breakdown` 全文と参照Definition of Doneを読了した。skillの既定保存先はタスク別所有規則に従って変更し、既存 `tasks/plan.md`、`tasks/todo.md` と他タスクを保持する。

現コードの根拠：`QwenDialog::dispatch_frame` はClose/Cancelを他action・pollに優先する。`ReadingController::prepare` はsnapshotと新しいPreparedIdを作り、`human_send` はConfirmingと同一IDを要求する。`restart` は旧preparedを捨てる。raw音声は再生用にdialogが保持し、閉じる/対象変更で破棄する。これらを表示変更によって迂回しない。

## 一つの縦割り作業単位 U1

範囲は音声準備→確認→明示送信→結果→再練習の1経路である。規模S（本体1、テスト1）。状態遷移・取消し・個人音声の外部送信が関係するため、難易度は中、リスクは高とする。ファイル数の少なさを低リスクの根拠にしない。

依存順は「P0 → 追加仕様/レビュー → 設計/レビュー → P1 → 独立テスト → 実装/焦点回帰 → 固定差分検証 → 独立レビュー → 親の受入報告」である。親承認済み仕様・設計をP1へ反映した。Astra独立仕様/設計レビューの証拠は本担当未取得であり、todoの未完了gateを維持する。親は独立する設計/テスト準備を並行するが、同一ファイルの並行編集は行わない。

## 必須検証と危険箇所

| リスク | 必要な証拠 |
| --- | --- |
| 自動準備が送信同意を代行する | 通常読込/録音完了→確認表示までmock通信0、表示したIDの明示click後1回。描画反復でIDを作り直さない。未設定/不正音声は送信不可 |
| 旧snapshot/古い音声の復活 | 音声変更/教材変更/再練習後の旧ID拒否、取消し/閉じるとsend・poll・audio load完了の同frame競合。既存競合回帰を継続 |
| 概要が実際の送信内容と異なる | 完了後①②の再展開が送信時の音声・英文と一致し、再送0、raw不変。Running/Failed/Cancelledでも誤送信導線を作らない |
| 見出しだけ変えて説明が旧位置に残る | 各状態の可視文字/操作を段階ごとに検査。初期3見出し、旧欄の不在、完了時折畳み/再展開、全文に到達する実描画 |
| 丁寧化で送信不確実性を弱める | NotSentとMayHaveBeenSent、遠隔停止/課金取消し不保証、閉じる時破棄を文意で照合。単純な文言置換だけを安全検証としない |
| 狭幅/拡大で終了や送信内容が隠れる | egui描画回帰＋合成native画面で標準/820×650/80～160%。キーボード操作は静止画とは別記 |

焦点コマンドは `cargo test --locked --bin wordweave5 qwen_reading_tests`。全体gateは `cargo fmt --all -- --check`、`cargo test --all-targets --locked`、`cargo build --release --locked --bin wordweave5`。全Cargoは親が指定した1担当へ集約する。runnerは前後の差分識別、exit code、件数/失敗/未検証を報告する。変更前REDは全件未取得であり、取得済みと扱わない。新規の状態安全試験を優先し、変更前失敗/変更後成功または妥当な同等証拠を残す。既存の独立test/取消し回帰を緩和しない。共通変更へ広がるなら単独package検証を再計画する。

## P1確定事項・次の引継ぎ

1. 上部固定①→②→③概要で長文時も全段階を示し、本文はスクロールする。送信前②の確認対象は非折畳みで全文に到達できる。UX3-AC-06の表示条件で検証する。
2. 送信開始を受理した時だけPreparedPreviewの表示情報をsent_previewへ保持する。「送信成功」は応答成功/遠隔処理完了を意味しない。閲覧専用でSend可否・ID照合へ使わず、再練習/対象変更/閉じるで消去する。raw音声・キーを複製/永続化しない。
3. 注記の丁寧化はQ3-AC-011の明示置換で解決した。例文・AI評価本文・見出し/ボタン名は案内文の語尾変換対象外である。
4. Input、有効音声・資格情報、録音/読込/入力エラーなしのときだけ既存prepareを用いる。previewは再生成しない。明示Sendのみ原音再生を止め、Close/Cancel優先・再練習後の新確認を維持する。

重大な要求未決はない。次は親が既定モデルで独立review/test担当へ承認済み仕様・設計・P1を引き継ぐ。上部概要の可視性、sent_preview寿命、取消し競合は実装/検証で立証する項目であり、文書確定だけで合格にしない。
