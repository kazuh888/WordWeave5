## 目的・出典・完了境界

読者は将来の国語・理科学習ツールへ機能を展開する開発者である。今回の成果はFrameworkの責任境界、既存4設計の補正、追加候補の採否と着手条件を、根拠と未決事項付きで判断できる文書一式である。

U01: 親から引き継いだ最新要求「Framework方針を今文書化、既存4設計を必要修正、優先/条件付きライブラリ候補を再評価し今必要なら設計、保留なら着手条件を記録」。U02: 同引継ぎの制限（文書のみ、追加設計最大3件、コード/API/EXE/設定/公開なし）。U03: 同引継ぎの達成条件（第二教科の出題→回答→評価→記録で確定し、部品二消費者検証とは別gate）。
継承制約C01は[AGENTS.md](../../AGENTS.md)、C02は[既存仕様](../REUSE-DESIGN-001/spec.md)と[全体設計](../../docs/reuse/README.md)の認証・同意・原本・保存・互換性である。[計画](plan.md)のF01–F06を下表で具体化する。U01–U03は親の要求引継ぎに基づき、将来の個別APIや数値上限の利用者指定を意味しない。

前提は一件の文書化作業である。候補IDは網羅性の識別子であり、製品分割や実装順を承認するcapability mapではない。Skillは仕様工程に限定する。所有は本書のみ、親が独立レビューと既存承認範囲との照合を行い採用してから設計の受入判断に用いる。

## 保持する安全契約と実装選択の分離

FW-AC03/06は、現行本体のChatGPT認証Codex app-server限定、API-key fallback禁止、Volta shim直接実行、system/user PATH探索、返却model/effortの非推測を維持する。明示的Qwen対応の方向性は承認済みだが、失敗時の自動転送、実API試験や本体規約更新の承認を含まない。
送信内容・宛先・用途と人の同意の対応、送信前取消しと送信後の結果不明、再取得と新規実行、AI生成成功と保存成功を区別する。原文・原音・inkを保護し、教材登録は案→可視差分→学習者承認を維持する。追記は既存内容/レビュー状態を保持し、修正とは分ける。部品が承認を代行したことにしない。
ここで観測する約束は文書上の責任・状態・根拠の整合である。crate名、型名、trait/enum、保存実装、配布方式は設計案であり、利用者の確定要求と区別する。API版・通信protocol版・保存形式版を同一視せず、切出しだけで既存形式を変更しない。

## 今回の証拠と将来の実行受入

今回の形式はMarkdownである。成果は`docs/reuse/`の全体設計・Framework・候補台帳・既存4件・追加最大3件とADR0003、受入記録は`tasks/FRAMEWORK-DESIGN-001/results.md`とする。正確な追加ファイル名/ADR名は親が計画とリンクを統一する。本書は文章・表の形式を既存仕様に合わせ、コード例が必要なら`proposed`と記す。本体コード/テストは変更しない。
実行する文書検査は `git diff --check -- tasks/FRAMEWORK-DESIGN-001 docs/reuse docs/decisions` と `git status --short`、対象Markdownの直接読取りによる空白・競合marker・fence/table・相対リンク/anchor検査である。未追跡文書をdiff検査だけで済ませず、開始状態と所有を照合する。内容の意味整合は独立レビューで確認し、docs-onlyのため本体試験/release buildは非該当である。
将来gate A（部品）: 実際の二消費者が同一版をコピーなしで利用し、独立adapterを持ち、相手固有の型・設定・保存先を要求しない。正常・境界・拒否・取消し・結果不明・保存失敗・互換性の該当ケースを実行観測する。最小試験アプリと実製品の実績を区別する。
将来gate B（Framework）: 英語と選定した第二教科で出題→回答→評価→記録を縦断し、教材・回答・評価基準・記録の教科固有の意味を分離できる証拠を得る。第二教科の課題/評価主体/記録項目を先に確定し、途中失敗時の記録整合も確認する。Aの合格だけではBの代替にならず、Bの実証後にFramework契約を確定する。実認証/API・実機入力・アクセシビリティ・評価品質は別受入とする。
