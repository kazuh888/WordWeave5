## 目的・要求の出典

英語チャットから教材案を作る際の引用拒否について、利用者が「何と何を比較して、なぜ拒否されたか」を識別できるようにする。単一能力「教材案の引用検証と拒否説明」の仕様である。

| 出典ID | 入力・位置づけ |
| --- | --- |
| U1 | 親から受領した利用者要求: 訂正モード・対象語 improve・4往復選択で「元の発言に存在しない引用です。」となる不具合を調査する。 |
| U2 | 親から受領した利用者要求: 「元の発言」が何を指すか分かるよう改善する。 |
| P1 | 親の追加制約: 厳密一致を維持し、空・過長・不一致を区別する。1始まりの元会話の往復番号、話者、引用、元文を識別表示する。生成指示でMarkdown・改行の保持を明示する。 |
| P2 | 親の追加制約: 保存済みDraftにも同一検証を適用する。曖昧照合・自動再生成・不正理由の削除・登録自動化をしない。実ログは複写せず合成例で検証する。 |
| G1 | AGENTS.md: 案→可視差分→学習者承認を経て登録する。既存教材・学習状態を保護し、追加と訂正を分離する。 |

観測済みコード: `src/material.rs` の生成応答検証は、snapshotと話者の解決後、空白のみ・2000文字超・非包含を同じ文言で拒否する。保存済み案の `validate_evidence` も同じ判定を別の一括文言で拒否する。文字数はRustの `chars().count()`、照合は `contains` である。

親から受領した今回の診断証拠: 最新ローカルrunの原文にはMarkdown強調があり、返却引用ではその記号が省略されていた。`exchange_index=3`、話者assistantの原文と引用が不一致であり、発言の欠落ではない。本担当は実ログを再収集していない。一般の全拒否原因をこの事象へ限定しない。暫定 [plan.md](plan.md) の「payload未取得」は親の最新診断により更新が必要である。

## 参照先・入力・出力

「元の発言」は、教材案作成要求時に固定した選択往復のうち、引用の `exchange_index` と `role` が指す発言本文である。後から編集された現在の会話本文、画面でMarkdownを解釈した表示文字列、教材本文ではない。

- 入力形式は既存JSONを維持する。`reasons[].quotes[]` は `exchange_index`（0始まりの元会話位置）、`role`（`user` / `assistant`）、`quote`（文字列）を持つ。JSONのエスケープを復号した文字列を照合する。
- 利用者表示は `往復 N`（元会話位置+1）、既存画面と対応する `あなた（質問）`（user）または `Codex（AIの回答）`（assistant）とする。選択した順番への振り直しはしない。選択が0番・3番なら表示は往復1・往復4である。
- 成功出力は従来の教材案、失敗出力は拒否理由と対象を説明する日本語テキストである。公開データ形式・保存形式は変更しない。
- 複数引用が不正な場合、少なくとも最初に検証失敗した引用の理由と対象を表示すればよい。全件列挙は要求しない。別の引用・話者の本文を代用品として表示しない。

2000文字はUnicodeスカラー値数である。UTF-8バイト数、表示幅、書記素数ではない。空白のみの判定は既存の `trim().is_empty()` と同一とする。引用はトリムしてから照合するのではなく、返却された文字列をそのまま照合する。複数条件を満たす場合は参照先→話者→空白のみ→過長→非包含の順で理由を選ぶ。JSON形式や変更理由そのものの既存検証は、この引用検証より先に失敗し得る。

## 画面・操作・失敗後の扱い

対象はチャットの「教材案を作成」操作後の既存エラー通知と、保存済み教材案の根拠検証エラーである。既存通知の折返し・縦スクロール・コピーを利用し、新規の専用ウィンドウ・操作・設定・ファイル出力は追加しない。標準幅と狭い幅でラベルと参照番号が読め、色だけに依存せず拒否理由を伝える。新しいポインター専用操作を追加しない。スクリーンリーダー対応の新規保証は範囲外であり、既存アクセシビリティを劣化させない。

失敗は警告付き成功ではない。自動再生成、自動修正、理由の削除、候補の自動登録はしない。利用者は元チャットを確認して既存の「教材案を作成」から明示的に再試行できる。同じ生成結果なら再度拒否され得る。作成中の既存キャンセル経路・キャンセル時の保存動作は変更しない。新しいタイムアウトや再試行回数は設定しない。失敗説明の永続保存、新しいログ、既存案の自動破棄は追加しない。

`reasons` は既存のJSON配列、各要素は `path`（文字列）、`reason`（文字列）、`quotes`（既存引用配列）である。生成JSONの構造、未知フィールド拒否、既存の教材案出力は維持する。

許可される配列内パスは `/examples/N/english`、`/examples/N/japanese`、`/examples/N/note`、`/replacements/N/phrase`、`/replacements/N/meaning`、`/replacements/N/conditions` に限る。
