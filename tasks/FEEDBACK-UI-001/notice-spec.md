## 2. 画面・操作・入出力

対象入口は、教材案生成の引用・根拠検査失敗と、UI内で保存案を再検査/登録前確認して同検査に失敗した場合である。一般通信失敗・保存I/O失敗・Storage読込時validationを引用不一致へ分類し直さない。

初期状態は次の順とする。比較と技術情報は閉じている。これはP5による具体化である。

1. 生成失敗なら「教材案を作成できなかった」、保存案再検査失敗なら「この案は登録できない」。教材に登録していないことと既存教材を変更していないことを示す。
2. 原因に即した短い平易な理由。例「AIが引用した文を、元の回答の中にそのまま見つけられなかった」。空白のみ・長さ超過・参照不存在・話者不正を同じ理由へ丸めない。
3. 「次にできること」として元の発言・選択対象の確認と、必要時の明示的な教材案作成再試行を案内する。誤引用に合わせた原文改変、成功保証、回数返却を案内しない。
4. 「引用と元の回答を確認」で比較を展開し、「閉じる」で通知を閉じる。固定元発言が利用者発言の場合、展開内容は「あなたの質問」と正しく識別し、上記ボタン名から話者を推測しない。

比較は上に「AIが示した引用」、下に「作成を依頼した時点の元の発言」を置く。最初の失敗理由・教材項目・往復・話者の対応を維持する。固定版を表示しており現在のチャット編集を反映しない旨を示す。複数引用のある理由でも、診断対象の引用とその参照元を対応させる。全失敗一覧は追加しない。

展開時は両本文とも「読みやすく表示」が初期選択であり、「原文を表示」と一括切替する。比較を閉じて同じ通知内で再展開した場合は選択モードを維持する。新しい通知受信・同文再通知・閉じた通知の再表示では初期状態へ戻す。これはP5による具体化である。

本文は編集不可で選択可能とし、全文をスクロールして確認できる。240文字で固定切断しない。段階的な描画・展開を用いる設計でも、全文へ到達する操作が必要である。「AI引用の原文をコピー」「元の発言の原文をコピー」は各本文の元文字列のみをコピーする。取得不能の側に有効な全文コピー操作を出さない。

技術情報には取得済みの理由番号・path・往復番号・role等を保持する。理由番号はAI応答内の理由の順序であり、教材番号ではない。未知pathは「対象項目を特定できない」、参照元不存在/不正話者等は「元の発言を取得できない」と識別し、既知の原因を添える。現在の会話・別往復・推測した話者で埋めない。

## 3. 表示形式・コピー契約

読みやすい表示の対応範囲は、行頭の `#`–`######` と空白による見出し、空行による段落、実改行、対になる `**太字**` / `*斜体*`、行頭の `- ` / `* ` / `+ ` および数字と `. ` による箇条書き、対になる単一バッククォート内のコード、三連バッククォートで囲んだコードブロックである。コード内はMarkdown装飾しない。入れ子・複雑な混在構文・その他Markdownへの完全準拠は約束しない。未対応構文や閉じていない記号は内容を失わない安全な文字表示とし、黙って本文を除去しない。

原文表示はMarkdownを解釈しない。実際の改行は改行として示し、文字列中のバックスラッシュと `n` の2文字はそのまま示す。CRLF/LF、前後空白、タブ、Unicode、Markdown記号を保存値上で書き換えない。表示不能な制御文字を安全な可視表現にする場合は原文との差を識別できるようにし、コピー元を変更しない。読みやすい表示では同じに見えても厳密な原文一致を意味しない旨を比較欄で短く説明する。

| 操作 | 出力する文字列 |
| --- | --- |
| 一般通知の「詳細をコピー」 | 従来の詳細文字列。構造化通知の契約を適用しない |
| 構造化通知の「診断情報をコピー」 | 結果・平易な理由・次の操作・取得済み技術識別情報・AI引用/固定元発言の各先頭240 Unicode scalar値の抜粋。欄を区別し「抜粋」と明記する。241以上では省略を明示する。取得不能はその理由。表示モード/開閉によらず同一内容 |
| 各本文の「原文をコピー」 | 明示操作した側の元文字列の全文のみ。見出し、抜粋用省略記号、装飾用文字を付加しない |

診断コピーの抜粋上限は旧Q03互換を利用したP5の具体化であり、閲覧や全文保持の上限ではない。コピー/選択はクリップボードへ明示操作で出すだけであり、外部送信・ファイル出力・教材保存を追加しない。

数値・validationは旧Q04を継承する。引用は空白のみ不可・2000文字以内・1–10件、理由説明2000文字以下・理由100件以下、許可pathと実在項目、検査順序を維持する。Markdown表示で正規化した文字列を照合しない。閲覧用の新しい数値上限は設けず、既存データ受付上限も緩和しない。

通知の開閉・表示モードは一時UI状態であり、永続schemaを変更しない。取消しは通知を閉じる操作である。失敗した案を登録できるようにする操作ではない。AI再試行は既存の明示操作だけとし、成功時も提案・可視差分・学習者承認を必要とする。
