# FEEDBACK-UI-001 U6 Markdown表示と教材登録結果の差分仕様

2026-09-29。状態: **親レビュー・承認待ち**。利用者が承認した対象を親の伝達に基づき具体化した文書である。authorは承認者ではない。所有は本書のみ、完了境界は要求・受入条件と未確定点の引渡しである。

## 1. 要求と境界

目的は、通知内の引用比較と英語チャットのAI回答を読みやすくし、教材案を承認して登録した結果を見落とさず識別できることである。既存U5の表示と同じ教材操作のフィードバックを改良する差分であり、独立した新サービスは追加しない。

| 根拠ID | 親が伝達した利用者要求・具体化 | 受入ID |
| --- | --- | --- |
| U6-R1 | 通知の引用と英語チャットAI回答の両方を、太字・表等を含むMarkdownとして読みやすく表示する | G01–G04 |
| U6-R2 | 一般的なMarkdown仕様を希望する。親はGFM採用方針を利用者へ明示済み | G01、G02 |
| U6-R3 | 教材案の明示承認後、登録成功/失敗を明確に知らせる。成功は対象語を示し、案が消えても見える | G05–G07 |
| U6-P1 | 原文コピー、strict引用照合、保存形式、生成プロトコル、登録承認を維持。AI回答がMarkdown対象、ユーザー本文はそのまま。通知の原文表示を維持 | G01、G03、G08 |

短縮ID `G01` 等は `FEEDBACK-UI-001-G01` 等を意味する。既存[notice-spec.md](notice-spec.md)のN01–N08を継承し、N03の限定Markdown範囲とN08の外部資源の扱いを本書の範囲へ更新する。N02の固定参照元、N04の全文到達、N05のコピー、N07の厳密検査は維持する。旧[spec.md](spec.md)の配色・日次上限は変更しない。

GFMはCommonMarkを基礎とする拡張仕様である。本書の約束は以下の安全な表示範囲であり、GitHub画面全体の再現やHTML実行を含まない。「Markdownは厳密に3種類」「GFMが普及順位1位」とは主張しない。参照: [GFM公式仕様 0.29-gfm](https://github.github.com/gfm/)。

## 2. 画面・入力・出力

### 2.1 読みやすい表示

対象は通知比較欄の「AIが示した引用」「作成を依頼した時点の元の発言」と、英語チャットに保存されたAI回答本文である。通知の固定元発言はユーザー発言の場合も比較対象として描画する。通常のチャットの「あなた」本文・入力欄はMarkdown化しない。話者、往復、取得済みmodel/effort、添付や教材根拠選択の対応を崩さない。

入力は既存の原文文字列である。表示用HTML等を保存しない。既存会話のAI回答にも適用し、再生成・移行を要求しない。通知の初期表示、比較展開、両本文の一括原文切替、閉じる/再表示はN02/N03/N06を維持する。チャットへの新しい原文切替UIは要求しないが、既存の全文コピーは原文を出す。

| 構文群 | 読みやすい表示での約束 |
| --- | --- |
| CommonMarkの本文 | 見出し、段落、強調/太字、引用ブロック、順序付き/順序なし/入れ子リスト、区切り線、コードスパン・コードブロック、エスケープを構造として表示する。コード内部は装飾を解釈しない |
| GFM拡張 | ヘッダー/セル/区切りを識別できる表、取り消し線、完了/未完了を判別できるタスクリストを表示する。表は見出し区切り行（例 `\| --- \| --- \|`）を備えたGFM構文を対象とし、区切り行のない縦棒付き行を推測で表へ変換しない。タスクリストは読み取り専用であり、チェック操作で原文を変更しない |
| リンク・自動リンク | 非操作の文字として表示する。表示からブラウザー起動・ネットワーク取得を行わない。リンク先は原文コピーまたは通知原文表示から確認できる |
| 画像・HTML | 画像を取得/描画せず、画像参照は代替文字と参照先を含む安全な文字として確認できる。HTMLは実行せず文字として表示する。空白へ置換して情報を消さない |
| 未閉鎖・非対応構文 | CommonMarkとして成立する部分は通常の構文規則で扱い、残りを安全な文字として読める。表示不能を理由に回答/引用そのものを拒否・削除しない |

通常の段落内改行と明示的改行の解釈はCommonMarkに従う。原文表示では実改行とliteral `\n`を区別し、CRLF/LF・空白・タブ・Unicode・記号を保存値とコピー元で変えない。読みやすい表示が同じでも原文一致を保証しない説明は通知比較欄に残す。閲覧用の新しい文字数/表サイズ上限を導入せず、長い内容はスクロール等で末尾まで到達させる。

### 2.2 教材登録の結果

入口は教材案の「内容を確認して教材に登録」である。案生成完了は登録成功ではない。提案・可視差分・学習者の明示承認、追加と訂正の区別、既存の登録可否検査を維持する。

成功結果は「対象語」と「教材への登録が完了したこと」を文字で示す。例えば合成語 `clarity` の成功なら「clarity の教材を登録した」と識別できる。登録処理と必要な保存が成功した後だけ表示する。案が直後に消えても、開いている教材登録ダイアログの本文スクロール外の先頭で確認できる。新しい成功通知ダイアログは自動で開かない。ダイアログを閉じた後も英語チャット画面の見える位置で同じ対象付き結果を確認できる。

成功結果は明示的に「登録結果を閉じる」操作を行うか、次の登録操作を開始するまで保持する。ダイアログを閉じる操作とは区別する。本文コピー、通知閲覧、案の消滅で消さない。再起動後の保持は不要であり、結果履歴や永続保存形式を追加しない。次の登録が失敗した際に古い成功を今回の結果として示さない。

| 結果 | 観測可能な説明・次の操作 |
| --- | --- |
| 登録前の拒否/検査失敗 | 登録できない理由を示す。登録ボタンの無効化と「理由を詳しく確認」の既存経路を維持し、拒否通知を発行する場合は既存auto-dialog方針を守る。引用不一致はU5の比較へ進める。失敗案の登録を許可しない |
| 保存完了前の失敗で、未反映と確認できる場合 | 成功を表示せず、対象と失敗原因を明示する。既存の案保持/復元・明示再試行経路を維持する。未登録/既存教材不変は確認できた範囲だけで述べる |
| 保存途中の失敗で復旧待ちの場合 | 「保存処理が途中で停止し、再起動時の復旧が必要」であることを明示する。未登録・既存教材不変・登録成功のいずれも断定しない。既存fatal/復旧表示と停止条件を維持し、再登録を先に案内しない |

警告/拒否/失敗の既存通知区分を維持する。結果の閲覧・閉じる・コピーは取消し/ロールバックではなく、AI再試行や再登録も開始しない。案の破棄や承認前にダイアログを閉じる場合は成功を表示しない。新しい取消し・自動再試行・復旧操作は追加しない。

## 3. 安定受入条件と例

## 4. 設計との分離・検証・未確定点

本書の約束は画面上の結果と入力/出力の保存である。パーサー/依存ライブラリ、共通rendererの配置、字体の実現方法、表の折返し/横スクロール、成功結果の内部型・通知との分離はdesignerが決める。外部依存の採用承認を本書で代行しない。既存技術背景はRust/egui、本体`src/`、回帰は既存`cfg(test)`/`tests/`、作業文書は当taskディレクトリである。例 `if self.settings_changed() { ... }` の既存snake_case/書式を継承するが、新API/実装コードは指定しない。

常に行う: 要求ID追跡、原文保護、既存差分・教材・学習状態保護。親へ返す: 表示対応の削減、未確認状態の結果断定、保存形式/生成プロトコル変更、外部取得の追加。行わない: 本体/test編集、Skill後続工程、再委任、実データ試験、commit/push/公開。

本書の静的確認は `git diff --check -- tasks/FEEDBACK-UI-001/gfm-spec.md`、参照先存在とG01–G08の要求対応である。アプリ受入は独立test author/runnerが焦点回帰とG04のWindows実描画を記録し、納品時に `cargo test --all-targets --locked` と `cargo build --release --locked --bin wordweave5` を行う。本書作成時点ではU6のアプリ受入証拠は未取得であり、U5合格を流用しない。

親レビューで確定する点: 「次の登録操作開始」を、次の案生成開始ではなく次の「内容を確認して教材に登録」の明示操作が受理された時点と解釈した。この解釈と第2.1節の具体的なGFM対応範囲を親が確認するまで、後続工程の確定契約としない。それ以外の未解決の利用者質問は現時点でない。親の既存ユーザー承認と仕様具体化承認を区別し、利用者への同じ許可の取り直しを要求しない。

計測: 子 `/root/gfm_receipt_spec`。起動指定は親記録を正とし、実行model/effort metadata・開始/終了tokenカウンター・親子包含関係は未取得である。通常shellはACL初期化エラー、読み取り専用の昇格再試行は成功した。担当成果物と静的確認のみを親へ渡し、計測共通ファイルは変更しない。
