# 音響解析・音読履歴の外部仕様案

2026-10-04 / ACOUSTIC-HISTORY-001 / S1 / v1。**親点検・独立レビューの指摘解消済み。利用者の「変更しました。実施してください。」を受け、実装段階へ移行した。未実装である。** [レビュー記録](review.md)／[実装計画](implementation.md)

## 1. 目的・根拠・承認境界

利用者が自分の音読を後から聴き直し、同じ英文・目標・条件の練習における音響的変化とQwen助言を辿れるようにする。原音保存および本設計に沿った実装開始は承認済みである。未実測の上限・配布条件は実装前の確認対象であり、実測により変更が必要な条件は黙って緩和しない。

直接の入力は親からの依頼と[計画](plan.md)のAH-R01–06である。元の利用者発言全文は本担当へ渡されていないため、要求の解釈は親レビューで照合する。現行の根拠は[音声I/O](../../docs/reuse/audio-io.md)と[Qwen評価](../../docs/reuse/qwen-audio.md)であり、そこにあるproposed契約を実装済みと読み替えない。

| 要求 | 利用者依頼の意味／既存制約 | 本仕様の受入ID |
| --- | --- | --- |
| AH-R01 | ローカル音響分析を設計する | AH-AC01、03、05、06、08 |
| AH-R02 | 原音とQwen評価を残し、後から辿る | AH-AC02、04、07–10、15、16 |
| AH-R03 | 練習の経過をグラフで見る | AH-AC10–13、17 |
| AH-R04 | 保存をデータ損失なく運用するための派生要件 | AH-AC04、08、09、14–16 |
| AH-R05 | 独立音声ツールと本体へ再利用する設計 | AH-AC18 |
| AH-R06 | 毎回の明示Qwen送信・アプリ別認証を維持する既存制約 | AH-AC07–09、18 |

能力境界は `audio-history`（固定入力と保存）、`local-analysis`（ローカル測定）、`qwen-advice`（明示送信と助言）、`practice-review`（履歴比較）である。履歴へ解析と助言を関連付け、比較は履歴と解析結果を読む。解析とQwenは相互に依存しない。提供順は履歴→解析／助言→比較を基本とし、実装時の依存関係は実装計画で管理する。

原音の保存、客観的な音響値、本人の練習目標、AIの助言を分ける。発音の正答率、総合点、自動合否、医療的判断、学習成績・復習間隔の自動更新、クラウド同期、Codexへの結果送信は対象外である。

## 2. 前提と提案値

- 初版はWindows上のWordWeave5と独立音声ツールを対象とする。全OS・全マイク・すべての話者に対する測定品質を保証しない。
- 「原音」はファイル入力なら検査時に固定した元ファイルbytes、録音ならRecorder.finishで得るmono PCM16 WAVである。録音前の多ch機器streamまで保存する意味ではない。再生・解析用PCMは派生物である。
- インポート音声は今回の本人の練習とは限らない。話者が本人であることと練習日時が未確認なら参考音声として保持し、既定の練習系列・回数から除外する。利用者が両方を確認したときに練習試行として記録できる。同一bytesの再取込みは既存記録との重複を表示し、回数を自動加算しない。別試行とする場合も重複を明示した人の確認を要求し、bytesだけから別の発話実績を推定しない。
- 初版はF0、相対的なデジタル信号レベル、録音時間、低エネルギー区間だけを提案する。音素位置合わせ、正しいアクセント・句切れの自動判定は含めない。
- 固定例文が同じでも、実際に別の文を読んだ音声は同条件の比較に含めない。「例文との一致」は未確認／本人確認／AI確認／不一致・確認競合を区別して保持する。Qwenを使わない場合も、原音を聞き返して本人が読上げ文を確認できる。AIの判定精度は保証せず、Qwenの参照不一致は既定系列から除外する。本人確認との競合は黙って上書きせず参考表示に留める。未確認・不一致でも原音保存と個別閲覧は可能である。
- 一致確認の対応は、既存Qwenの `Assessed` をAI確認、`ReferenceMismatch` を不一致、`Unassessable`・未送信・失敗を未確認とする提案である。本人確認またはAI確認があれば一致確認条件を満たすが、不一致・競合を優先して除外する。本人とAIそれぞれの根拠を保持し、後勝ちの単一値に置換しない。これはAIの実際の文一致精度を確認済みとする契約ではない。
- 比較を成立させる収録条件は、既知の機器・入力形式・前処理に、利用者が確認する同一の距離／ゲイン／環境プロフィールを加える。機器IDや同じラベルだけで実環境が同一と保証しない。不明な条件は不明のまま保存する。
- 保存期限は設けず、自動削除しない。容量の提案既定値は履歴全体2GiB、80%到達で警告、次の保存で上限超過なら保存を開始しない。ごみ箱のデータと結果も容量に含み、ごみ箱へ移動しても空きは増えない。初版には完全削除を含めない。上限変更は明示操作とし、現在量を下回る設定では既存履歴を保持したまま新規保存を止める。上限増加は実disk不足を解消する操作ではない。これは性能測定に基づく確定値ではない。
- ローカル解析は同時1件、1回の処理時間上限60秒を提案する。待ち行列への自動投入はしない。展開音声・派生データ・作業領域の最大量は設計で見積り後に提案を確定する。上限の不確定を無制限実行の許可にしない。

## 4. 入出力・測定の意味

入力のWordWeave5互換profileは、既存録音UIの30秒上限と、ファイル入力WAV／MP3／AAC／AMR／3GP／3GPPの現行codec制限、元bytes 6MiB以下、復号後60秒以下、8–48kHz、1／2chを維持する。WAVは既存strict PCM16入口を維持する。詳細codecと依存ツール条件は[既存形式仕様](../QWEN-FORMATS-001/spec.md)を正本とし、拡張子のみでは受理しない。黙った切詰め・正規化・resampleで入力条件を満たさない。非空partial録音の既存warningは消さない。

参照英文は既存の空白のみ不可・Unicode scalar 10,000以下を維持する。保存時の本文・教材識別子と版を固定し、後日の教材編集は過去の本文を変更しない。教材が消失しても履歴の固定文を表示できる。履歴からの再評価は、元教材を更新する操作ではない。練習目標は任意の平文（提案上限1,000 Unicode scalar）、各試行の振り返りは任意の平文（提案上限2,000）とし、超過時は明示エラーで保存を拒否する。勝手な切詰めはしない。目標変更は新しい目標版を作り、過去試行を再分類しない。

| 出力 | 表示・単位・欠測 | 解釈上の限界 |
| --- | --- | --- |
| F0 | 解析上有効なframeのHz時系列、中央値・P10–P90、有効frameの割合。無声／推定不能frameは欠測と理由 | 話者の良し悪し・アクセントの正しさではない。誤追跡・倍／半周波数誤りを含み得る |
| 信号レベル | フルスケール基準のRMS dBFSの時系列と全体値。演算不能は欠測。完全ゼロ信号は「デジタル無音」であり有限の0dBFSにしない | 音圧dB SPLや校正済み声量ではない。ゲイン、距離、機器、codec、前処理の影響を受ける |
| 時間 | 復号された録音全長を秒で示す。低エネルギー区間は開始・終了秒、合計秒、全長に対する割合 | 録音全長は言語的な発話時間ではない。低エネルギー区間は休止・無音の候補であり、雑音下の休止や無声子音を正確に識別する保証はない |
| Qwen結果 | 既存の評価済み／評価不能／参照不一致、検証済み助言、指定model／effortと取得できた返却値 | 形式適合は内容の正しさを保証しない。結果を音響指標と合算した点数にしない |

時系列の時刻は原音先頭を0秒とする。保存精度と表示の丸めを分け、表示提案は時間0.01秒、Hz整数、dBFSと割合小数1桁とする。丸めを超える精度を保証する意味ではない。低エネルギー判定閾値・frame幅・F0範囲等は解析profileの版付き設定として確認可能にする。初期値の正しさ・適用範囲は設計と後続検証で決める。

履歴の論理出力は、試行ID、原音の検査可能な同一性情報、固定参照、日時・時差、目標版、収録条件、原音warning、各処理ID・状態・失敗分類、入力／engine／設定／指標の版、保存済み結果、振り返りである。UTF-8文字列を用いる構造化記録と原音bytesをバックアップ対象とする。JSON／DBの物理形式、path、hash方式、公開API署名は内部設計の選択であり、本仕様は固定しない。秘密キーと未検証raw応答は履歴・バックアップ・エラーへ含めない。

## 6. エラー・阻止・回復の共通規則

エラーは少なくとも入力不正、形式非対応、依存欠落、解析失敗／上限、容量不足、書込拒否、他writer使用中、破損／未知版、取消し、Qwen既存の固定エラーと送信確実性に分ける。日本語で対象・失敗した操作・保存済み範囲・次に可能な操作を示す。秘密値、未検証HTTP本文、元音声bytesをエラーへ含めない。

保存中に取消された場合、commit前なら未保存、commit済みなら保存済みとして残す。完了との競合が確定するまで「取消要求中」とし、利用者がデータの存在を誤認する取消完了表示をしない。ローカル解析の取消し／timeoutで部分値を完成値へ昇格しない。エラー解消後の再試行は同じ処理の人の操作であり、別処理や外部送信を連鎖させない。

試行詳細のウィンドウだけを閉じる操作は処理取消しではない。開始済みの処理と結果保存はhost側で継続し、一覧に処理中を表示する。再表示は同じ試行へ戻る。明示的な処理取消し・ごみ箱移動・アプリ終了は別操作であり、実行中または未保存の内容があれば影響を確認する。アプリ終了を取り消した場合は処理を維持し、終了を確定した場合は取消し・未確定状態の保存を行う。送信済みQwenの遠隔停止は保証しない。

破損原音は再生／解析／送信を止め、保存済みの他結果を出所と「原音を検証できない」表示付きで読めるようにする。未知版の履歴は書換えず、対応版が必要と示す。解析engine更新は履歴形式更新と区別し、旧結果を読める範囲を明示する。過去のメモリ専用セッションから失われた音声・助言は復元可能と説明しない。

音読履歴部分の復元の既定提案は取り込みである。既存教材・Progress全体の復元方式を取り込みへ変更する意味ではない。同じ試行ID・同じ内容は重複させず、同じIDで内容が異なる場合は当該履歴復元の全適用を停止し競合を示す。履歴の置換復元や自動競合解決は初版へ含めない。

完全削除は次段階の設計事項として保留する。既存Progressの日別snapshot・復旧参照、共有原音、古い保存rootやbackupの再取込みによる再出現を扱う必要がある。削除台帳等の方式とその寿命・復元契約を設計せず、ファイル削除だけで完全削除を約束しない。初版のごみ箱では容量を解放できない制約を、保存管理と容量超過時の案内に表示する。この提供範囲は親の設計提案であり、利用者承認済みではない。
