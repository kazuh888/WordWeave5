## 範囲と判定根拠

- 所有は本書のみ。計画者の指定は `gpt-6-astra` / `high`、実行metadataは未取得である。[計画](plan.md)のT1に従い、`agent-skills:test-driven-development` を期待値・独立oracle・RED引継ぎの設計へ適用した。
- 原音永続化の許可と具体的な受入条件の承認を分ける。AH-AC01–18の採否と解析profileを確定してから実行可能なテスト／REDへ進む。本書は実装着手の承認ではない。
- 期待値は仕様から導く。設計・実装の値を正解として記録しない。個別不具合の報告に対する再現依頼ではないため、今回はバグ再現の成否を判定しない。
- 各ケースは原則として実ローカル保存・復号・解析・再読込を用いる。通信と資格情報は外部／秘密境界で代替し、disk障害・commit前後の中断だけ明示的な障害注入を用いる。POST数は送信契約の観測であり内部呼出順への依存ではない。
- ケースごとに専用一時rootを作り、元入力・WordWeave5 root・独立ツールroot・backup出力を分離する。実教材・実録音・既定保存root・Windows実資格情報を参照しない。削除は自身の一時fixture内に限る。

## 合成fixtureとoracle

| 記号 | 構成／独立した正解 |
| --- | --- |
| F-SIGNAL | PCM16合成WAV。16kHz、1ch、1秒の200Hz正弦波、振幅約0.5と約0.25、全ゼロ、一定seed雑音、clip、1frame未満。8／48kHz・2ch版も用意する。元bytesと復号sample列を別途固定する |

| F-BOUND | 6MiB・60秒・8–48kHz・1/2ch、各上限の直前／一致／直後を他条件適合で個別生成する。偽拡張子、未対応codec、空／破損、空白英文、文字数境界も含む。形式条件は[既存仕様](../QWEN-FORMATS-001/spec.md)から生成する |
| F-FAULT | 専用rootの書込拒否／容量不足／競合writer／原音破損／未知版と、各永続化境界で一度だけ失敗・強制終了するdriver。固定clockと明示barrierで順序を制御し、sleepへの依存を避ける |
| F-QWEN | 外部通信境界で評価済み／評価不能／参照不一致／不正応答／timeout／遅延完了／metadata欠落を返す代替transport。送信内容・POST数・実行IDを観測する。秘密は検出用sentinelのみで、保存物・ログ・backupへ出ないことを検査する |

F0は正弦波の既知周波数と独立参照器を照合する。Hz・倍／半周波数誤り・有効frame割合・許容誤差をengine実測後に承認し、現在の出力へ合わせない。雑音が常にF0欠測になるとは仮定しない。全無声fixtureの妥当性は別途確立する。

読上げ文の一致には次のAH-AC11副ケースを含める。状態制御の正しさを試験するものであり、合成音声や代替応答だけからAIの文一致判定精度を主張しない。

- AC11-a: 同じ固定例文Aに別の文Bの音声を関連付け、F-QWENが `reference_mismatch` を返す。既定系列から除外し、原音・固定文・不一致と出所を保存する。
- AC11-b: Qwen未使用・一致未確認の音声は保存／個別再生可、既定系列には入らない。原音聞返し後に本人が「この例文を読んだ」と確認し、他条件が一致する場合だけ追加する。POST増分0、出所は本人確認である。
- AC11-c: 本人確認済みの試行へAI不一致、AI不一致の試行へ本人一致を逆順でも適用する。両方の根拠と確認競合を保持し、既定系列から除外する。後勝ちの一致で黙って上書きしない。
- AC11-d: AI一致だけを持つ試行の出所をAI確認として表示し、本人確認や実際の一致を保証した表示にしない。各状態を再起動／backup復元しても出所と除外判定が一致する。

## commit境界・取消し・再起動の共通行列

物理commit点は設計確定後に対応付ける。原音publish、試行固定情報commit、ローカル結果commit、Qwen実行／結果状態commit、注記commit、trash／復元commit、backup公開、履歴restore適用の各境界へ同じ行列を展開し、未対応点を残さない。

| 障害位置／操作 | 再起動後の期待 |
| --- | --- |
| commit直前に書込失敗・取消し・強制終了 | 直前の確定状態を保持し成功表示しない。固定情報未commitの原音は回復候補として保持する。メモリ結果は未保存／不足と分かる状態であり、成功結果を捏造しない |
| commit直後・UI成功通知前に強制終了 | 確定した状態を1件だけ再読込できる。再試行で重複試行・重複結果・POSTを増やさない。取消し要求が競合した場合も保存済み事実を隠さない |
| 複数対象のrestore適用途中で失敗 | 履歴は適用前の全体か、完了した新全体のいずれか。部分置換・参照切れ・既存原音消失なし。未完了backupを正常backupとして提示しない |
| Qwen送信開始後・結果保存前に強制終了 | 送信済み／結果不明の可能性を保ち、未送信・評価完了へ推定しない。再起動でPOST 0。新たな人の送信確認と保存だけ再試行を分ける |
| 取消し／trash後に旧job完了、直後に別試行を開始 | jobと試行の同一性を確認し旧結果を現在画面・別試行へ採用しない。保存済み入力と新試行に損失なし |
| windowだけ閉じる→job完了→同じ試行を再表示、別試行の閲覧も挟む | 元試行へ結果が1回だけ保存され再表示できる。追加POST・再解析0。別試行へ描画／保存しない。アプリ終了確認の取消しでもjobを維持する |

上記はアプリ強制終了試験である。OS電源断耐性を主張するには別のdisk耐久性検証が必要であり、process終了試験だけで代用しない。

## 後続RED・実施担当への引継ぎ

1. AC採否・解析profile・誤差基準の承認後、各ACをテスト名へ対応付け、所有するテストファイル／`cfg(test)` 節を親が割り当てる。共有Rustファイルは本体担当と編集順を合意する。
2. focused commandはリポジトリのCargo構成へ合わせて `cargo test --locked <確定したケース名> -- --exact` を基本とし、targetとcase名を実在確認して固定する。名前未確定の本書コマンドを実行済み証拠にしない。
3. 新機能未実装による期待失敗は、保存後再起動で試行／原音を取得できない、欠測／除外集合の不一致、保存再試行でPOSTが増える等の契約違反である。compile error・fixture生成失敗・実行0件は行動のREDと区別する。既存契約のテストが初回から通る場合は維持確認として分類する。
4. テスト作者から親経由で実装／実施担当へ、AC副ケースID、fixture式／期待ledger、commit障害点、実行command・対象差分、実際の失敗assertionを渡す。通すための期待値緩和、現実装からのoracle生成、黙った仕様変更をしない。
5. 将来のWindows提供gateは `cargo test --all-targets --locked` と `cargo build --release --locked --bin wordweave5`。保存・取消し・認証・広いUIは独立レビューも必要である。今回は文書のみであるため未実行である。

実音声のF0誤追跡・話者／環境ごとの品質、Qwen助言内容、Windows録音／再生／IME、screen reader、engine導入／配布・license・性能は別gateである。実音声／実API試験は後続の許諾と送信確認に従い、合成fixture成功を実証品質へ拡張しない。分析の時間上限・資源量・取消し完了時間の数値は未確定であり、承認後に境界試験を追加する。

本担当の利用量開始／終了カウンターと包含関係は未取得である。文書検査は行末空白、相対リンク、AC18件の一意な対応、所有範囲を対象とし、検査結果を親へ返す。本書は動作試験の合格報告ではない。
