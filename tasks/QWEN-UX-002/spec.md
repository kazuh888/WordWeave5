## 目的・出典・能力境界

音読評価の失敗から次の操作を理解でき、朗読画面とAI接続画面を情報の優先順で操作できることを目的とする。一次要求は親から受領した要約であり、原会話は本担当で直接確認していない。事実と原因未確定事項は [evidence.md](evidence.md) に従う。

| --- | --- | --- |
| QU-R1 | 別英文のMP3を送った際のResponseInvalidを理解できるようにする | `reading-feedback` / QU-AC-001～003 |
| QU-R2 | 目的→例文→操作→状態→フッターの階層、余白・見出し・区切り、詳細折畳み、警告の理由と次操作、冗長な取消し削除、冒頭注記維持 | `reading-dialog` / QU-AC-004～008 |
| QU-R3 | Codex/Qwenの接続設定UXを揃え、Qwenの接続確認を追加 | `connection-settings` / QU-AC-009～015 |
| QU-R4 | 既存の認証分離・保存/取消し・形式上限・互換性・利用者データ保護を継承。新UIのSkill化は利用者受入後 | 全能力 / QU-AC-016～018 |

## 入出力・上限・状態

入力形式/上限は [QWEN-FORMATS-001](../QWEN-FORMATS-001/spec.md) を継承する。6形式、6,291,456 bytes以下、復号後0秒超60秒以下、8～48kHz、1～2ch、録音最大30秒、参照10,000 Unicode scalar以下かつ空白のみ不可である。折畳みは制限を撤廃しない。

評価出力は [QWEN-SETTINGS-001](../QWEN-SETTINGS-001/spec.md) の`assessed`/`reference_mismatch`/`unassessable`、6必須項目、summary/理由2,000文字、heard_text10,000文字、改善field1,000文字、配列各8件、JSON 65,536 bytes以下を維持する。未知field・欠落・型違い・区分との不整合は拒否する。新しい評価点数や履歴を追加しない。

接続入力は同仕様の6地域、WorkspaceId 1～63文字、HTTPS、userinfo/port/query/fragment等の拒否・正規化を継承する。接続確認のレスポンスは公式一覧APIの`success`と`output.models[].model`を検査し、HTTP成功だけで一覧取得成功にしない。空一覧/対象不在は対象未確認、必要構造欠落・型違いは不正応答である。公式資料と4 Workspace掲載地域/SG・HKの差は [evidence.md](evidence.md) を根拠とし、SG/HKも接続先を変えず、未対応応答なら未対応とする。

接続確認は有限の待機時間/応答容量で打切り、取消しに応答する。具体的な上限値、進捗表示文言、HTTP失敗と安全な原因区分の対応表は設計で明記して親へ戻す。既存評価の最大180秒・非再送を接続確認の値として黙って流用しない。接続確認は推論を行わないが、料金が常に無料であるとは表示しない。

通常フローは音声準備→送信内容確認→明示送信→結果/失敗→再練習である。再練習は再準備へ戻り、旧確認を再利用しない。設定未完、録音/読込中、入力不正、確認前、進行中重複では評価送信を許可しない。ファイル選択dialogだけを取消した場合の既存選択保持も維持する。

## 実装選択・検証・引継ぎ

P-U01は親採用：Codexの既存入力を保持しQwenを同ページの展開編集にする。旧QS-AC-010の「専用modal」だけを置換し、QS-AC-010～014の保存/取消し/画面終了保護を継承する。背景クリックのmodal閉鎖という操作はinlineにはなく、別領域を操作しただけで編集値を破棄しない。

`response_format: {"type":"json_object"}`の追加は親提示の予防的な実装候補であり、JSON形式不正の減少を狙う。公式が未対応とする`json_schema`を要求しない。これは過去の失敗原因確定・応答成功保証ではなく、項目整合検証を省く根拠にもならない。型名、診断詳細の内部表現、eguiレイアウトの数値、非同期worker、HTTP/store実装は設計に委ねる。

既存Rust/eguiと`src/app`、`tools/qwen-audio`、既存test配置・Rust命名/format規約を継承する。コード例や新しい依存の選定は本仕様に追加しない。後工程は`cargo fmt --all -- --check`、`cargo test --all-targets --locked`、`cargo build --release --locked --bin wordweave5`と単独packageの関連test/互換確認を行う。仕様のみの本担当はリンク・ID・要求追跡を確認する。

- Always：所有specのみ編集し、既存dirtyを保持する。利用者要求・既存契約・親の採用・仮説を区別する。
- 親へ戻す：接続確認の時間/容量上限と区分対応、実現不能な保存/取消し保証、新しい外部公開形式、要求範囲や安全境界の変更。
- Never：アプリ/テスト編集、再委任、実データ/実API試験、commit/push/公開、無承認のSkill作成を行わない。

未解決事項は過去のResponseInvalidの具体的な発生段階、実APIでのJSON指定効果、6地域の実接続と対象モデル利用可否、native読み上げの成立、新UIの利用者受入である。仕様担当がこれらを合格へ書き換えない。起動指定はAstra/high、実行model/effortメタデータとKPI開始/終了カウンターは未取得である。
