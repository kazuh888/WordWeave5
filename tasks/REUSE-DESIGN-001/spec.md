## 目的・出典・範囲

利用者が承認した依頼（親からの引継ぎ、U01）は「再利用の全体設計と音声評価/Qwen・Codex app-server・Markdown表示・チャットの境界をMarkdownで文書化」である。親によるD02補足では、Codexのみから明示的Qwen対応へ拡張する方向性も承認済みである。読者は別ツールへ組み込む開発者であり、責任・根拠・未決事項を追跡できる文書一式を成果とする。

U02は引継ぎの権限境界（実装、設定変更、実API、実データ利用、commit/push/公開は未承認）、C01は[AGENTS.md](../../AGENTS.md)の認証・教材承認・データ保存制約である。以下のR02–R07はU01を検証可能にする派生要件であり、利用者が将来の個別APIを指定・承認したとの主張ではない。[計画](plan.md)のR01–R07/AC01–AC07を同じ番号で正式化する。

本書の所有は外部仕様担当のみである。対象は一つの文書化作業であり、下表の四機能は記述対象を識別するもので、製品の分割・実装順を承認するcapability mapではない。Skillの仕様工程だけを適用し、後続実装工程へ進めない。親は本書のレビュー・承認状態を確定してから設計の受入判断に用いる。

## 今回の確認と将来の実行基準

今回の観測対象はMarkdown文書である。ACは内容の有無だけでなく、主体・状態・根拠・承認状態の整合性を独立レビューで判定する。文書の技術スタックはMarkdownであり、Rustコード例は説明用の`proposed`で実装・コンパイル保証ではない。記述例は「現行: GUI/controllerが同意を担う。提案: 共通入口の承認契約。未検証: 実接続と評価品質」である。

親の実施記録先は`tasks/REUSE-DESIGN-001/results.md`である。全体設計、四機能文書、設計判断の記録をACへ対応付ける。ADRの最終ファイル名は親が計画と相互リンクを統一する。未作成の成果物パスは予定であり、最終確認時に存在を確かめる。

```powershell
git diff --check -- tasks/REUSE-DESIGN-001 docs/reuse docs/decisions
git status --short
```

未追跡ファイルは上記diff検査だけでは検査済みにならない。対象文書を直接読み、空白・競合marker・fence/table構造・相対リンク先とanchorを確認する。開始状態と変更所有を照合し、他者の既存/並行変更を本作業の変更と誤認しない。本体試験・release buildはdocs-onlyのため今回非該当である。

将来の実装承認後には、同一版をコピーなしで使う二消費者で、入力検証、正常結果、上限境界、拒否・取消し・結果不明・保存失敗、互換性を実行観測する。各adapterが相手固有の型・設定・保存先を必要としないことも確認する。実認証・実API・音声評価品質・実機アクセシビリティはmockや文書レビューと別の証拠で判定する。今回その実行・合格は主張しない。
