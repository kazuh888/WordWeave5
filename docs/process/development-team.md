# 開発の7役体制

2026-09-26 / DEVELOPMENT-TEAM-001。WordWeave5の開発用エージェント定義であり、アプリ内AIのモデル・認証設定ではない。

## 担当とSkill

| 担当 / エージェント名 | モデル | 主な既存Skill | 所有する成果物 |
| --- | --- | --- | --- |
| 計画 / `ww-planner` | `gpt-6-astra` 固定 | `agent-skills:planning-and-task-breakdown` | 計画、作業単位、モデル割当 |
| 外部仕様 / `ww-spec-author` | `gpt-6-astra` 固定 | `agent-skills:spec-driven-development` の仕様工程 | 利用者から見た動作・受入条件 |
| 設計 / `ww-designer` | 計画者が選定 | `agent-skills:api-and-interface-design`、UI時は `wordweave-egui-ui` | 内部構造・状態・データ・障害時設計 |
| 実装 / `ww-implementer` | 計画者が選定 | `wordweave-change`、UI時は `wordweave-egui-ui` | 割当範囲の本体コード |
| テスト作成 / `ww-test-author` | 計画者が選定 | `agent-skills:test-driven-development` のテスト作成工程 | 独立した回帰テスト、ケース、隔離fixture |
| テスト実施 / `ww-test-runner` | 計画者が選定 | `wordweave-change` の検証・結果報告 | 実行結果、ログ、未検証項目 |
| レビュー / `ww-reviewer` | 計画者が選定 | コードは `agent-skills:code-review-and-quality`、仕様は `review-external-specification`、設計は `review-software-design` | 根拠付き指摘、対象範囲・判定 |

既存Skillを利用し、新規Skillは作成しない。Skillは起動時に利用可能一覧から名前で解決して全文を読む。バージョン付きユーザーキャッシュの絶対パスを定義へ固定しない。未導入・未検出の場合は明示して止め、無断でインストールや別Skillへの置換をしない。工程を横断するSkillでも、担当工程を越えて他役の成果物を変更しない。

## モデル割当と起動前確認

- 親エージェントは利用者との窓口・起動・統合を担い、親のモデル/effortは変更しない。計画者は推奨するだけでなく、各作業単位の5役のモデル選定を行う。
- 計画・外部仕様の定義だけに `model = "gpt-6-astra"` を設定する。他の5役は `model` と `model_reasoning_effort` を省略する。固定値を入れると起動時の計画者指定を上書きするためである。
- 起動担当は、現在の呼出可能一覧を計画者へ渡す。モデル名・effort・理由を計画書へ記録し、対応する起動引数へ明示する。effortを変えない場合も `inherit` と記録し、継承値の対応可否を確認する。固定2役も継承effortがAstraで利用可能か確認する。
- 未指定・未対応・一覧にないモデルを推測して起動しない。計画者へ再選定を依頼する。指定された固定モデルが使えない場合は利用者へ戻す。モデル選定権は、権限・検証基準・ユーザーデータ利用・公開範囲を変える権限ではない。
- 難易度は変更ファイル数だけでなく、不確実性、影響範囲、状態遷移、永続化/取消し/認証、失敗時の損失、テストの判定困難さで判断する。明確で限定的な作業と、横断的・高リスクな作業で選定を分ける。モデル名から合格や実測性能を推定しない。
- 起動指定と実行メタデータを区別して記録する。実行モデル/effortを取得できなければ「未取得」とし、自己申告だけで実行値を確認済みにしない。

これはプロンプトと手順による統制であり、自動モデルルーターやファイル単位ACLの実装ではない。TOMLの構文成功だけでは、アプリでの検出・指定モデルでの起動成功を意味しない。

起動担当の必須チェックは、(1) 計画者指定のモデルと呼出可能一覧の照合、(2) 明示または継承effortの対応確認、(3) 起動指定と取得できた実行メタデータの別記録、である。固定2役も例外にしない。継承値を確認できず対応可否が不明なら、起動前に対応する明示値を確定する。実行メタデータが返らない場合は値を推定せず「未取得」と報告する。

## 進め方と引継ぎ

1. 親が対象・完了条件と作業IDを確認し、計画者を起動する。計画者は初期の作業順・役割・モデル・リスク・検証を定義する。
2. 外部仕様担当が要求を観測可能な受入条件へ落とす。仕様レビューと利用者確認を経て、計画者が作業単位を更新する。
3. 設計担当が内部構造を設計し、必要な設計レビューを行う。重大な仕様不明点は外部仕様へ戻す。
4. テスト作成担当が仕様に基づく期待値と回帰を作る。実装担当へ引き継ぎ、期待値を実装へ都合よく変更しない。
5. 実装担当が修正・焦点を絞ったテストを行う。テスト実施担当は固定した対象差分で必要な全体検証を行う。
6. レビュー担当が実装・テスト・証拠を独立確認する。指摘は各担当へ戻し、変更の影響がある検証だけ再実行する。最終受入と公開権限は利用者に残す。

小修正でも7役の責任は識別するが、全役を同時に常駐させない。既存仕様/設計の再利用や工程非該当は計画へ根拠を記録し、必要な確認を省略しない。質問・状況報告だけなら開発工程を起動しない。並列実行は独立した範囲のみ、通常は補助1役ずつとし、同時実行枠を変更しない。

引継ぎは短くし、最低限次を含める。

- 作業ID、担当役、依頼範囲/対象外、入力成果物と承認状態。
- 要求/受入条件ID、対象commitまたは未コミット差分の識別、担当ファイル/節。
- 計画者指定のmodel/effort、理由、必要なSkill。
- 出力先、検証コマンド、データ安全・公開等の制約、未解決事項。

作業文書は `tasks/<task-id>/plan.md`、`spec.md`、`design.md`、`tests.md`、`results.md` に必要なものだけ作る。作業リストは同ディレクトリの `todo.md`、現状の索引は `tasks/current.md` とする。既存の `tasks/plan.md`・`tasks/todo.md` は未完了作業を保持し、自動で移動・上書きしない。

## 独立性と安全境界

- 書込み担当は他の作業者と共有している前提で、所有ファイル/節以外を変更せず、他者の編集を戻さない。Rustの本体と `cfg(test)` が同じファイルなら順番に編集する。
- 計画/仕様/設計担当は担当文書のみ、テスト作成担当はテスト/fixtureのみ、実装担当は本体のみを編集する。テスト実施担当はログ・報告・隔離データ・ビルド生成物のみ書き、ソースや期待値を変更しない。
- レビュー担当はread-only設定で、自分の指摘を自分で修正して承認しない。親が報告を保存する。ホストの実行時権限が優先され得るため、起動時にも権限を確認する。
- 子からの再委任、独断のcommit/push/merge、実データでの試験は禁止する。リポジトリ既存の検証条件と教材登録時の利用者承認を維持する。
- 計画者選定と独立レビューは別の責任である。レビュー担当がモデル不足や検証不足を検出した場合は根拠を示し、計画者へ再選定/検証追加を返す。計画者は不合格を単に合格へ書き換えない。

## 導入確認

定義は `.codex/agents/ww-*.toml` に置く。既存 `ww-scout` は限定的な読み取り調査用として保持し、7役の代替にはしない。

静的確認：7定義のTOML構文、名前・必須項目、固定2役/可変5役、権限、Skill参照先、既存定義の保存を確認する。実行時確認：役名がホストに検出され、計画書のモデルを指定して起動できることを次の開発開始時に確認する。検出できない場合は再読込/新規セッションで確認し、別役・別モデルに黙って置換しない。

根拠：[Codex custom agents / model precedence](https://learn.chatgpt.com/docs/agent-configuration/subagents)。モデル未指定は継承され、カスタム定義内の指定値は起動時指定より優先する。
