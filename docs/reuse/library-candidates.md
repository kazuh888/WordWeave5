# ライブラリ候補と着手条件

2026-10-03 / FRAMEWORK-DESIGN-001。[Framework方針](framework.md)を踏まえた判定台帳である。「今設計」は今回の文書化であり、今すぐ切出し実装するという意味ではない。
設計が揃ったこと、試験用の利用先で動くこと、二つの実製品で再利用されたことを別々に記録する。

## 1. 判定の基準

- 今設計: 既存4設計の境界に影響し、現行ソースで責任を限定でき、第二利用先の具体的な候補を挙げられる。
- 保留: 現在は一製品の方針に依存し、分離を先に決めると誤った共通化や小さすぎる部品を増やす。
- 「利用先候補」は実利用実績ではない。ライブラリ数を増やすことを目標にせず、同じ版を変更せずに使える範囲を確かめる。

## 2. 優先して設計する3候補

| ID / 候補 | 今設計する理由・根拠 | 境界と利用先候補 | 設計書 / 切出しを始める条件 |
| --- | --- | --- | --- |
| L01 音声入出力 | [Recorder](../../src/media.rs)・[Speaker](../../src/media/speech.rs)とQwen評価の入出力条件を分ける必要がある | 録音/再生/ローカルTTS。評価・採点・UI・保存設定は外。WordWeaveと独立音読ツール | [音声I/O](audio-io.md)。第二利用先が実際に必要とする操作/OSを仕様化し、フォーマット差・取消し/seek・デバイス障害の契約試験を用意した時 |
| L02 添付原本管理 | [AssetStore](../../src/assets.rs)をchatと音声評価が異なる上限で扱うため、原本/派生物/送信同意の境界が先に必要 | 不変原本・検証・参照。GC、教材寿命、preview、AI送信許可は外。WordWeaveとノート/音読ツール | [原本管理](asset-store.md)。第二hostの保存root・参照寿命を定め、既存原本との互換・保存失敗試験を用意した時 |
| L03 egui共通controls | [本体](../../src/app/controls.rs)と[独立ツール](../../tools/qwen-audio/src/controls.rs)に字形位置補正があり、挙動差もある | ボタン等の狭い表示/操作契約。画面構成・教材行・設定保存は外。WordWeaveとQwen GUI | [共通controls](egui-controls.md)。両利用先の例外・狭幅・scaleをfixture化し、現行補正差の採否を描画/操作で確認した時 |

この3件は互いの導入を必須にしない。たとえば音声評価はホスト提供WAVでも利用でき、マイク初期化やasset storeを必須にしない。
L01の捕捉音声がL02へ保存できてもQwenの入力条件を満たすとは限らない。形式変換の要否は送信先adapterが判定し、原本を保持して派生物を作る。
L03はMarkdown rendererと同じUI層の候補だが、一つの巨大UI packageに統合するかは切出し時の依存を見て決める。

## 3. 利用先が具体化してから設計する6候補

| ID / 候補 | 今は保留する理由・ソース | 保留中も守る境界 | 再開する具体条件・最初に検証すること |
| --- | --- | --- | --- |
| L04 通知・安全な診断記録 | [通知](../../src/app/notifications.rs)は教材の原因/登録receiptと密結合。[診断](../../src/diagnostics.rs)はglobal sinkとWordWeave用保存規約を持つ | 操作結果・対処action・表示方針と、秘密を含めない機械記録を分ける。raw応答の共通ログ化は禁止 | 第二hostで通知/診断が必要になった時。各hostの自動表示基準・保持期間を列挙し、instance別保存、成功/失敗/結果不明、秘密非記録を検証。通知と診断を一部品にする必然性も再判定 |
| L05 差分表示 | [material_diff](../../src/material_diff.rs)の行/path/意味はEntry依存。文字spanの共通化だけでは小さすぎる可能性がある | 原文比較と描画を、教材操作の意味・承認・commitから分ける | 第二hostで構造差分の確認操作が必要になった時。長文/Unicode/削除/狭幅、schema別の項目名、比較の省略表示を確認。差分閲覧を承認操作の代用にしない |
| L06 手書き・注釈 | [ink](../../src/ink.rs)・[annotation](../../src/annotation.rs)はegui、固定下地、PNG/JSON保存と結び付く | stroke原本、下地、描画、画像化、文字認識を分ける。原本を認識結果で置換しない | 国語の筆記か理科の図/式入力などの用途が決まった時。筆圧/消しゴム/座標/下地変更の必要性を仕様化し、実penと保存復元を確認。現行canvasが全用途対応とはしない |
| L07 安全な保存処理 | [atomic_write](../../src/store.rs)と[commit](../../src/commit.rs)・[backup](../../src/backup.rs)では責任が違う | 単一file置換、複数file整合、domain移行を混ぜない。OS横断の耐障害性を推測しない | 複数の独立repositoryで同じ原子的置換契約が必要になった時。実filesystem障害/競合/復旧を試験し、既存依存で足りるか先に確認。バックアップ全体は教科/host所有のまま |
| L08 資格情報管理 | 現行QwenのWindows資格情報とCodexのChatGPT認証は同一方式でない | 秘密の取得口、host namespace、接続世代を分ける。Codex失敗時のAPI-key fallbackは禁止 | 複数のAPI接続でOS保管・移行・権限が重複した時。分離されたnamespaceと削除/更新/取消しを検証。認証方式まで共通化しない |
| L09 MCP/子プロセス支援 | QwenツールのMCPとCodex app-serverはprotocol・同意・回復が異なる | 起動/pipe/終了回収の仕組みと、各protocol・権限判断を分ける | 第二の実サービスで共通な生命周期が確認された時。所有processだけの回収、EOF/親crash/標準入出力の境界を試験。汎用MCPサーバー化や遠隔公開は別承認 |

保留は「将来必ずライブラリ化する」予約ではない。条件を満たしても既存部品の利用やhost内moduleで十分なら、独立ライブラリを作らない判断を残す。

## 4. Frameworkが追加する検討対象

上記9件は技術部品の候補である。教科横断という利用先を追加したため、別軸で以下を[Framework方針](framework.md)に設計した。

| 対象 | 今決めること | 保留すること / 再開条件 |
| --- | --- | --- |
| 学習進行・試行記録の外枠 | 教材版/回答/評価/保存結果を分け、教科adapter経由にする | 最終型・永続schema・crate。第二教科の縦断仕様を選んだ時 |
| 復習候補選択 | 仕組みと教科の評価→復習方針を分ける | 現行scheduler全体の抽出・普遍的間隔モデル。第二教科でも復習要件があり意味が一致した時 |
| 教材・採点・学習目標 | 各教科/問題形式が所有する | 全教科共通schema、自動採点の妥当性。実際の課題・評価者・品質基準が揃った時 |

以前の「学習記録はWordWeave側」は一般ツール向け技術部品への混入を防ぐ判断である。学習ツール間に限定したcore候補まで否定するものではない。
ただし現行ProgressやEntryをそのまま共通化する根拠にもならない。この範囲の違いを既存設計へ補足する。

## 5. 次回の着手チェック

次のplanner/設計担当は、ライブラリ切出しまたは第二教科の仕様作成を始める際に本台帳を確認する。利用者が実装の範囲を承認し、担当者が以下を成果物へ記録する。

1. 対象IDと実利用先、その場で重複している責任、単純な内部moduleで足りない理由。
2. hostと部品の所有、入力/保存形式の版、実OS/デバイス、同意と原本保持、失敗/復帰の受入条件。
3. 試験用hostと実製品での結果を区別し、既存機能の回帰を確認する。コードコピーや片方固有の設定を要求しない。
4. 本台帳の状態を「設計中/検証中/再利用確認/取り下げ」へ更新し、判断・証拠・残る条件へリンクする。

見直しの契機は第二利用先の決定、教科固有条件の共通coreへの侵入、保存/認証の変更、ライブラリ配布前である。期限だけで一斉抽出を始めない。
判断者は後続taskのplannerと設計担当、境界の変更は独立レビュー対象である。今回の受入は[作業記録](../../tasks/FRAMEWORK-DESIGN-001/results.md)に残す。
