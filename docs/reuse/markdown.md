# Markdown表示の再利用設計

2026-10-02 / REUSE-DESIGN-001 / 論理機能ID `markdown`。

状態：現在の表示処理を根拠とする切出し設計案（proposed）。独立crateは未作成である。[全体設計](README.md)の安全・互換性・移行原則に従う。

## 1. 用途と対象外

AIの回答や引用を、原文を変えずに読みやすく表示する。チャット、通知、設計資料のプレビューなどで利用する。Markdownの編集、HTMLの実行、Webブラウザー、コード実行、画像の取得、ファイルを開く権限は担当しない。

基本はCommonMarkを解析する既存parserと、表・取消線・タスクリストの拡張を組み合わせた表示である。GFMの全仕様やGitHubと同じ見た目を保証するものではない。独自parserを作らず、対応書式と安全方針をライブラリの契約にする。

## 2. 現行の根拠と対応表

- [表示実装](../../src/app/notifications/markdown.rs)の `parse_nodes`、`inlines`、`blocks`、`table`、`show`。
- [Cargo.toml](../../Cargo.toml)：`pulldown-cmark = 0.13.0`、`eframe = 0.31.1`。現在はWindows依存に含まれる。
- [呼出し境界](../../src/app/notifications.rs)の `show_markdown`。通知、[チャット](../../src/app/chat_ui.rs)、[教材案確認](../../src/app/material_review.rs)から使用する。
- [フォント設定](../../src/app.rs)の `heading` familyと、[既存受入試験](../../src/app/gfm_tests.rs)。renderer内テストも本体harnessへ依存する。

| 入力 | 現行表示 | 切出し時に維持する条件 |
| --- | --- | --- |
| 段落・見出し | 折返し本文、少し大きい見出し | 見出し階層を失わず解析する。現行は見出しレベルごとのサイズ差なし |
| `**太字**`、斜体、取消線 | フォント・装飾に反映 | 日本語でも太字が見えること。フォントを利用アプリから渡せること |
| 順序/箇条書き・引用・入れ子 | 記号、インデント、引用線を表示 | 深い入れ子でスタックを使い尽くさず、狭幅を圧迫しない |
| 区切り行を含むパイプ表 | 見出し行、列揃え、折返し、横スクロール | 長いセルと次行を重ねず、表だけ横スクロールする |
| `- [x]` / `- [ ]` | 読取専用のチェック表現 | クリックで保存内容を変更しない |
| インライン/ブロックコード | 等幅表示。ブロックは横スクロール | 実行しない。コード文字をMarkdownとして再解釈しない |
| Markdownリンク | ラベルの通常文字表示 | 現行はクリック操作なし。宛先を勝手に開かない |
| Markdown画像 | 代替文字と宛先を文字で表示 | 画像取得・ローカルファイル読取・外部アクセスなし |
| HTML・スクリプト記述 | 文字として表示 | HTMLとして実行しない |
| 未完の記号や対応外書式 | parserと現在の表示規則に従う | エラーを隠して原文を書き換えず、原文表示へ戻れること |

脚注・数式・Mermaid・シンタックスハイライト・GFMの全拡張は対応を約束しない。単に `| A | B |` と一行書くだけでは表と判定されない場合がある。表の例は次の形である。

```markdown
| 語 | 意味 |
| --- | --- |
| improve | 改善する |
| strengthen | 強める |
```

## 3. 目標の境界

```text
アプリが保持する正本の文字列
  → 解析（明示した書式profileと入力上限）
  → 不変の表示document
  → egui renderer（幅、フォント、色、安定したwidget ID）
  → 描画結果・制限通知
```

解析結果から元のMarkdownを再生成して正本の代わりにしない。教材の引用照合、保存、全文コピーには、アプリが保持した正本を使う。JSONの復号は呼出し側が一度だけ行う。入力に本物の改行があればparserの改行規則に従い、文字としての `\n` を無差別に改行へ置き換えない。

解析とegui描画は論理上分ける。ただし、他rendererがない段階で独自の大規模な文書ASTを公開仕様にしない。parserの内部型は公開しない。最初は同一crate内の非公開解析部とし、UIなし解析が必要になった時にfeatureまたは小packageとして独立させる。

### 公開面の案（未実装）

| 入口/型の仮称 | 入力 | 出力・保証 |
| --- | --- | --- |
| `MarkdownSource` | アプリが提供する不変UTF-8文字列 | 解析・表示中も内容を変更しない |
| `RenderProfile` | 許可する拡張、入力/複雑さ上限 | 未指定時のprofileを版ごとに固定する |
| `prepare` | 原文とprofile | 不変document、または分類された制限エラー |
| `show` | document、`egui::Ui`、安定ID、幅、style | 描画結果と通知。ファイル/通信/clipboardへの副作用なし |
| `MarkdownStyle` | 本文・太字・等幅フォント、色、余白 | WordWeaveの固定family名やWindowsのfont pathを要求しない |

次は利用順序の疑似コードであり、現行APIとしてコンパイルできるコードではない。

```text
source = 保存済み回答の正本
document = prepare(source, profile)
show(document, ui, 回答ごとのID, 利用可能幅, アプリのstyle)
コピー操作 → アプリがsourceをclipboardへ入れる
原文表示操作 → アプリがsourceを整形せず表示する
```

rendererはアプリ全体のテーマを変更せず、渡された表示領域だけに描画する。親の縦スクロールはアプリが所有し、表/コードの横スクロールだけをrendererが所有する。同じIDを複数文書で使い回してスクロール状態を共有しない。

キーボードでの原文/整形表示の切替、全文コピー、フォーカス順はアプリが提供する。rendererの選択可能ラベルだけで全文コピーやスクリーンリーダー対応を達成したとは扱わない。日本語フォントの欠落を事前確認し、読み上げ支援・キーボード選択・スクロールの到達性は利用先の実画面で別途確認する。現行ソースの静的確認では、その全操作は未検証である。

## 4. 安全・制限・異常系

目標profileの上限は、初期案としてUTF-8原文1MiB、解析node 100,000、表128列とする。これは新規の設計値であり、現行rendererが実装済みの上限ではない。切出し時に境界試験と実測で妥当性を確認する。高負荷入力でも無制限の処理を約束しない。

- 超過は `DocumentTooLarge` / `ComplexityLimit` として返し、通常の全文表示に見せかけて切り捨てない。アプリは理由と、上限内の原文抜粋・全文保存/コピー等の代替操作を表示する。未制限の全文描画に自動fallbackしない。
- 空入力は空表示として成功する。Markdownとして不完全な文字列も通常の入力であり、破損した教材とは扱わない。
- 制限チェックは大量allocate後に行うだけでは不十分である。原文byte上限は解析前、node/表列上限は解析中に適用する。
- 外部画像・HTML・リンクの自動実行は禁止する。将来リンク操作を追加する場合は、rendererが `LinkRequested` を返し、アプリのscheme/宛先許可を通す別契約とする。現版では操作APIを追加しない。
- parserや依存ライブラリの更新で解釈が変わり得る。対応profileの試験を通し、互換性に影響する差を記録する。
- キャッシュを導入する場合はアプリの責任で寿命・上限を持つ。内容ID・profile版と文書を対応させ、違う原文を古い解析結果で表示しない。色や幅の変更は再描画へ反映する。

通常の描画に通信・保存はなく、取消しや再送のAPIは不要である。大きな文書をバックグラウンドで準備する場合だけ、アプリ側で世代IDを付け、古い結果を採用しない。

## 5. 切出しと検証

1. 現行の描画関数を独立境界へ移す。通知からのラッパーは残し、本体の呼出し変更を限定する。
2. 固定の `heading` family/コード背景色をstyleへ移し、本体の既存フォント・配色を渡して見た目を維持する。
3. 本体harnessに依存しない合成入力の試験を追加し、既存の本体試験も維持する。
4. 制限profileを別の観測可能な変更として試験する。切出しだけの差分と混ぜて既存挙動の後退を隠さない。
5. 独立した最小表示アプリとWordWeave5で、同じライブラリ版を使って表示する。最小アプリを第二の製品実績とは称さない。

第二の実製品候補は、教材機能を持たないRust/eguiのノート支援ツールである。採用を確定した製品ではなく、チャット設計の第二候補と同じ利用先を想定する。ノート側adapterが原文の読出し・保存/コピー、フォント・テーマ、縦スクロール、原文/整形表示切替を担い、WordWeaveの通知や教材型には依存しない。
両製品が同じライブラリ版・構文profileを参照し、下表の同一合成入力をそれぞれの画面で検証する。正常表示だけでなく上限の直前/一致/超過、危険な宛先、狭幅時の到達性、原文byte列の不変を確認する。両方の製品adapterで確認できて初めて実利用による再利用性の受入とし、最小表示アプリの成功だけで代用しない。

| 試験 | 観測する合格条件 |
| --- | --- |
| 原文保存/コピー | 表示前後で正本のbyte列が同じ。Markdown記号・空白・改行を保持 |
| 日本語の太字・表・リスト | 太字のfontが適用され、長いセルと行が重ならない。構文と見た目の両方を確認 |
| 狭幅・長いコード・深い引用 | 親UIを横へ押し広げない。局所横スクロールで到達できる |
| 危険な宛先・HTML・画像 | 通信、ファイル読取、OSのURL起動、コード実行が0件 |
| 上限と上限+1 | 指定単位で境界を判定し、超過理由を返す。描画へ無制限にfallbackしない |
| 独立消費者 | `WordApp`、学習データ、WordWeave font名、通知harnessなしで動く |
| 依存更新 | 同じ合成入力の構造・描画・正本保持を比較し、変更を明記 |

不具合が出た場合は本体ラッパーを旧表示処理へ戻す。保存形式は変えないため、保存済みMarkdownや引用の逆変換・データ移行は不要である。古い版で表示不能でも原文を破棄しない。

## Framework観点の補足（2026-10-03）

[Framework](framework.md)の問題・解説でも、既存のCommonMarkと限定GFM拡張の表示範囲を維持する。Framework専用型や教材への依存は追加しない。
国語のルビ・縦書き、理科の数式・構造図・対話的図表は既存Markdown対応からは保証できない。必要な課題が具体化したら別rendererまたは明示的な拡張profileを選び、原文と表示代替の契約を定める。今回、HTML実行や外部画像取得を解禁しない。
Markdownは回答評価器ではない。装飾・表・改行の描画結果を採点入力や引用の正本にせず、教科adapterが明示した入力schemaを使う。
スタイル/フォント/操作の一部は[egui controls](egui-controls.md)と共通化を検討できるが、部品同士を必須依存にしない。狭幅/日本語/実機アクセシビリティの受入は継続する。
解析・安全制限・コピー・スクロール責任の既存契約は変更不要である。今回の証拠は[追補結果](../../tasks/FRAMEWORK-DESIGN-001/results.md)を参照する。

## 6. 未決事項

最終crate名、フォント配布、MSRV、別UI向けrendererは切出しの時に決める。egui以外で同じ画面部品を使えるとは主張しない。対応するMarkdown書式の意味・正本保持・安全方針は共有できるが、画面の実装はUI技術ごとに必要である。
