# 教科を増やせる学習Frameworkの方針

2026-10-03 / FRAMEWORK-DESIGN-001。**境界を定める設計案であり、Frameworkの完成・実装を示すものではない。** [全体設計](README.md)、[候補台帳](library-candidates.md)、[判断記録](../decisions/0003-learning-framework-boundaries.md)を合わせて読む。

## 1. 今決めること、実証後に決めること

目標は英語・国語・理科の学習ツールが、同じ版の共通基盤を使えることである。既存アプリを複製して教材名だけ変える方式は採らない。
一方、まだ第二教科の要件がないため、全教科を表す教材schema、万能採点API、動的plugin機構は確定しない。

ここでのライブラリは「ホストが必要な処理を呼び出す部品」、Frameworkは「学習の進行を管理し、教科側の出題・評価・記録adapterを呼び分ける枠組み」である。
技術部品が再利用できても、教科横断の学習Frameworkが成立した証拠にはならない。今は責任境界と守る条件を固定し、最小の制御契約は第二教科で検証してから固定する。
一つのアプリで教科を切り替えるか、教科ごとのアプリを作るかは未決である。どちらにも独立した保存先・設定を注入できる境界を保つ。

## 2. 現行のままではFrameworkでない理由

| 確認したソース | 教科横断利用の障害 | 分離する意味 |
| --- | --- | --- |
| [Entry / Example / Skill](../../src/model.rs) | 英単語、社外メール、英日例文、語句・綴り/聞き取り等を前提とする | 教材形式、問題種、正解判定は教科側 |
| [Exercise](../../src/learning.rs) | 日本語・対象英語・参照英文、語彙追加の検査を持つ | 国語の記述や理科の単位付き回答へ流用しない |
| [make_queue / Memory](../../src/scheduler.rs) | Entry/Skill/Progressとヒント文字数に依存する | 復習候補選択の仕組みと、学習項目・ヒントの意味を分ける |
| [Progress](../../src/store.rs) | 設定、復習、会話、教材案、教材出典等が同居する | 教科の記録とホスト保存形式をそのまま共通coreにしない |

例えば現行の文字列正規化は大文字小文字等を同一視する。理科の記号・単位や、国語の表記評価にそのまま適用すると正誤を変え得る。
現行schedulerは独自の目安であり、学習効果や特定の記憶モデルへの適合を保証しない。共通化によって教育的妥当性が増したとは扱わない。

## 3. 目標の責任と依存方向

```text
各ホスト（英語 / 国語 / 理科のアプリ、または同一アプリの教科選択）
  ├─ 画面・設定・利用者確認・保存先・実行を組み立てる
  ├─ 学習の進行core（候補）
  │    └─ coreが定める窓口 ← 教科adapter / 保存adapterが実装
  └─ 必要な技術部品だけを利用
       Codex / 音読評価 / Markdown / chat / 音声I/O / assets / egui controls

英語adapter → 学習窓口       学習core → 英語Entry/WordApp は禁止
技術部品 → 学習core/教科型 は不要（学習以外のツールでも利用する）
```

| 層・担当 | 責任 | 持たせないもの |
| --- | --- | --- |
| 教科非依存の技術部品 | 通信、原本保持、描画、録音等の限定した能力 | 学年、正答、教材登録、教科の教育目標 |
| 学習進行core候補 | 試行の識別、進行状態、結果と対象の対応、記録要求 | 英語field、採点rubric、音読点数の意味、具体DB/画面 |
| 教科・問題形式adapter | 教材検査、出題、回答表現、評価基準、学習上の反映方針 | 他教科の条件分岐を共通coreへ増やすこと |
| ホストcontroller / repository | 人の操作、同意、設定、永続化、競合・未保存表示、組立て | AIの生成成功を保存・学習成功と見なすこと |

「教科が違う」だけで別Frameworkにせず、「記述・選択・数値・読み上げ」等の問題形式の差もadapterで検証する。
ただし問題形式の全組合せや共通plugin登録APIは今作らない。英語も特権的な組込み型ではなく、一つのadapterにする目標である。

## 4. 学習境界の最小契約案

以下は責任を検討するための論理名であり、公開Rust型・保存schemaの確定ではない。

| 窓口・データ | 入出力 / 所有 | 不変条件 |
| --- | --- | --- |
| 教材参照 | 教科namespace、教材ID、版。正本は教科repository | 表示名・並び順をIDにしない。教材変更後も過去の出題版を辿れる |
| 出題準備 | 教材版、問題形式、出題条件 → 固定された問題/評価条件 | 正解やrubricの公開範囲は教科が決め、学習者用表示と分ける |
| 回答snapshot | 試行ID、回答本文/構造、asset参照 | 評価に使う回答を固定する。表示整形・音声認識で原本を書き換えない |
| 評価adapter | 問題/回答/基準の固定版 → 評価案、評価不能、失敗 | 人・規則・AIを区別し、評価根拠と評価器の版を保持する |
| 記録要求 | 試行ID、教材版、回答参照、評価、確定操作 → 保存結果 | 同じ試行の重複適用を拒否。保存成功後だけ保存済みとする |
| 復習policy | 確定した学習イベント → 次回候補/保留 | 生のAI点数をそのままGradeや復習間隔へ変換しない |

共通の記録外枠は識別・版・関連・状態までに絞る。評価の中身は教科/問題形式の版付きschemaで検査する。
すべてを無検査のJSONや単一の正誤booleanに入れる設計は採らない。未知の教科schemaは保持/読み取り専用などの互換方針を決め、推測して採点・上書きしない。
回答payloadの具体型、評価尺度、namespaceの発行方法は第二教科の仕様時に決める。基盤側が低水準の上限を検査しても、意味の検査を代行したとはしない。

## 5. 進行・保存・取消し

通常は「出題と基準を固定 → 回答を固定 → 評価 → 評価内容を確認/確定 → 記録を保存 → 必要なら復習を更新」である。
外部AIを使う場合は評価の前に送信対象・宛先・目的の確認を挟む。ローカル規則評価に不要なAI同意を強制するわけではない。

| 場面 | 必要な扱い |
| --- | --- |
| 評価中に回答・教材が変わる | 実行IDと固定版へ結果を結び付ける。現在の回答へ自動適用しない |
| AI待機の取消し・timeout | ローカル終了と遠隔中断を区別する。結果不明で自動再生成・自動採点しない |
| 評価不能 | 不正解や0点へ変換しない。原音不足等の理由と再操作を教科側が示す |
| 評価完了・保存失敗 | 評価/回答を未保存として保持し、同じ内容の保存だけ再試行する |
| 重複・遅延結果 / 削除された対象 | 実行ID・試行ID・版・削除状態を検査し、二重記録や別問題への適用を拒否する |
| 記録保存済み・復習更新失敗 | 同じイベントから更新を再開できるようにする。評価や回答を再生成しない |

試行と復習更新の保存を一体にできないhostでは、保存イベントIDと適用済みIDで冪等に更新する設計を要求する。具体的なtransaction方式はrepositoryの設計で確定する。
coreは保存要求を作り、正本保存と競合防止はhostが担う。保存ack以前のクラッシュでメモリ結果が必ず復旧するとは保証しない。
自動確定を許す問題形式/評価方法と、人の確認が必要な評価は教科仕様で明示する。AIの助言を無条件で正式な成績にしない。
WordWeaveの教材更新はこの試行記録とは別であり、**教材案 → 可視差分 → 学習者承認 → 保存**を維持する。追加のみでは既存内容・復習状態を保つ。

## 6. 既存4設計への影響

| 既存部品 | Frameworkからの使い方 | 今回必要な補正 |
| --- | --- | --- |
| [Qwen音読評価](qwen-audio.md) | 評価adapterが必要な場合だけ呼ぶ能力 | 英文音読の助言は国語/理科の採点ではない。助言→評価→記録は別 |
| [Codex接続](codex-app-server.md) | 教科adapterの依頼を運ぶ通信部 | 教科prompt/schema/採点/登録権限を通信部へ入れない |
| [Markdown](markdown.md) | 問題や解説を必要な範囲で描画 | 数式・ルビ・図を既存Markdown対応と見なさない。原文保持は継続 |
| [chat](chat.md) | 学習の補助会話として独立利用 | Conversationと学習試行を統合しない。出典/試行は明示参照で対応 |

認証、固定入力、秘密の非記録、Codex exact回復とQwenメモリ取得の違いは変えない。共通Frameworkを理由に全LLMを同一能力と見なさない。
技術部品はFrameworkを使わないノートアプリ等からも利用できる。Frameworkを各ライブラリの必須依存にはしない。

## 7. 第二教科による確定gate

第二教科の第一候補は国語の短い記述問題とする。英単語照合と異なるrubric・部分評価を検証できるためである。ただし開発着手・対象学年の承認ではない。
理科の数値/単位問題は別形式の反例として設計点検に使い、第二教科一件だけで全教科対応済みとは宣言しない。

| ケース | 最小の縦断内容 | 区別すべき事実 |
| --- | --- | --- |
| 英語（基準） | 一つの既存問題を出題、回答、既存基準で評価、記録 | 既存教材・記録の意味を変えず、英語adapter経由でも動く |
| 国語（候補） | 短文を読み、記述回答、rubric項目ごとの根拠付き評価、記録 | 表記ゆれと内容理解を別に扱い、評価不能/要確認を表現できる |
| 理科（境界点検） | 数値と単位を入力し、許容誤差・単位・必要な根拠を検査 | 大文字小文字、数値と単位、途中式の評価方針を英語の正規化から独立させる |

実装着手前に利用者・仕様担当が一つの教科/問題と受入fixtureを選ぶ。小さな隔離データだけで次を実行確認する。

1. 英語と第二教科が同じ版の進行coreを使い、出題→回答→評価→保存まで通る。coreに教科名の分岐やEntry/Progress依存を足さない。
2. 教科の入力検査/評価基準を差し替え、保存済み教材・回答・原本を変更せず既存fixtureが再読できる。
3. 保存失敗、遅延/重複、取消し、評価不能、教材改訂後の結果で誤適用0件、自動再生成0回、原本変更0件を確認する。
4. 復習更新の重複・失敗が元の回答/評価を失わせない。二つのhostまたは教科adapterの保存先・設定が混線しない。
5. 初期gateは人/ローカル規則の評価adapterでよい。AI評価品質は別のデータ・基準・人の点検で確認し、接続試験で代替しない。

以上は将来の実行受入であり、今回の文書レビューでは未実施である。試験用hostで成立したことと、二製品で継続運用できたことも別に記録する。

## 8. 移行・保留・再検討

最初は既存保存形式の外にadapterを置き、旧データを読む経路と復帰経路を保つ。学習coreの公開型と保存schemaは別々に版管理する。
保存変更が必要なら、バックアップ、移行検証、旧版への復帰可否を先に定める。未知field・過去教材版・会話出典を切出しの副作用で失わせない。
全画面の共通化、全教科教材schema、動的plugin、遠隔配布/同期、汎用採点サービス、C ABI、他OS対応は今回確定しない。

再検討は第二教科の外部仕様着手時、別言語/別UIの利用先決定時、共通coreに教科条件分岐が必要になった時に行う。
担当は後続タスクのplannerと設計担当、契約の採否は利用者承認を含む仕様/設計レビューで決める。[候補台帳](library-candidates.md)をその開始時の必読資料とする。
今回の文書受入・非変更検査・未決事項は[作業記録](../../tasks/FRAMEWORK-DESIGN-001/results.md)へ集約する。
