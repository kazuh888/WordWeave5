# 音響解析と練習履歴の再利用境界

2026-10-04 / ACOUSTIC-HISTORY-001。**設計案であり、実装済み機能ではない。**

正本は[外部仕様](../../tasks/ACOUSTIC-HISTORY-001/spec.md)と[内部設計](../../tasks/ACOUSTIC-HISTORY-001/design.md)である。算出式・保存schema・状態遷移は内部設計に一元化し、本書は他のツールから利用する際の入口とする。

## 1. 分ける責任

```text
WordWeave5 / 独立音読ツール（各host）
 ├─ 音声I/O：録音・再生
 ├─ acoustic-analysis：ローカルPCM → 版付き測定結果
 ├─ qwen-audio：確認済みの原音と例文 → AIの助言
 └─ hostの履歴管理：原音・参照文・結果・目標・比較・保存/削除
```

| 部分 | 持つ責任 | 持たない責任 |
| --- | --- | --- |
| 音声I/O・復号adapter | 形式検査、原音から解析用PCM生成、録音/再生 | 練習成績、AI送信、保持期間 |
| acoustic-analysis（仮称） | 音高・デジタル信号の強さ・時間区間の測定、品質flag、欠測、処理版 | 教材型、言語の正解、発音採点、資格情報、UI、履歴root |
| qwen-audio | 既存の明示送信・接続・応答検証 | ローカル解析の自動外部送信、履歴の一括送信 |
| hostの履歴管理 | 試行ID、固定例文・目標、原本参照、保存、比較条件、バックアップ | 測定値を無条件に成績へ変換すること |

解析用の型から `WordApp`・`Entry`・`Progress` を参照しない。例文も解析器の必須入力にしない。将来の国語・理科ツールは同じ測定器を使い、何を練習するか・結果をどう解釈するかを各教科adapterで定める。

## 2. 最初の実装候補

音高推定はPraatの独立プロセス、単純なエネルギー・時間測定はRustとする案である。既存FFmpeg/ffprobeは復号に利用する。librosaを使う別adapterは可能だが、初版でPython環境まで必須にする案は採らない。根拠と未検証事項は[調査記録](../../tasks/ACOUSTIC-HISTORY-001/evidence.md)に残す。

解析器の処理版と設定を結果に残す。異なるエンジン・設定で得た値を同じ系列へ黙って混ぜない。原本を残すことで、後で同じ条件による再解析が可能になる。再解析はローカル操作であり、Qwenへの再送信とは別である。

## 3. 保存と配布の境界

原音は取り込んだファイルのbytes、録音時は録音処理が確定したWAVのbytesを保存する。録音機器内部の未取得信号まで復元可能とはしない。解析用PCMは派生物であり、原音を置換しない。

保存root・バックアップ・削除・容量管理はhostが所有する。別アプリの履歴や資格情報を自動共有しない。初版の履歴管理はWordWeave5内の実装とし、第二hostで保存契約まで一致する証拠が得られるまでは、汎用永続化Frameworkへ拡張しない。

Praatの導入版・配布条件・障害時回収、二hostで同じ解析libraryを呼ぶ契約試験は実装時の受入事項である。文書を作成しただけでは共通libraryによる動作や解析精度を確認したことにならない。

## 4. 関連設計との関係

- [音声I/O](audio-io.md)：解析・評価を録音/再生の責任に含めない。
- [Qwen接続](qwen-audio.md)：現行のメモリ保持に対し、今回host側の履歴保存を追加設計する。送信の都度確認する境界は変えない。
- [原本管理](asset-store.md)：不変bytesの検証原則を再利用するが、既存添付の全件inventoryや削除方針を音読履歴へ無条件に流用しない。
- [Framework](framework.md)：測定器は技術層、発音練習の目標と解釈は教科層、保有・復元はhost層である。

履歴グラフは測定の変化を示す。本人の目標・振り返り・原音の比較と合わせて上達を確認する。検証されていない総合点やレーダーチャートの尺度は作らない。
