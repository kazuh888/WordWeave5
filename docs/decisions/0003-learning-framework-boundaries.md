# 0003: 教科横断Frameworkは境界を先に定め、第二教科で確定する

2026-10-03 / FRAMEWORK-DESIGN-001。

## 状態

設計方針として採用。実装・共通crateの抽出・第二教科製品の開発承認ではない。
[0002](0002-reusable-library-boundaries.md)の機能別ライブラリ方針を維持し、学習ツール間のFrameworkという利用範囲を追加する。

## 背景

利用者は、国語・理科の学習ツールにも展開し、既存機能を同じライブラリとして再利用する意向を示した。
現行のEntry/Skill/Progressは英語教材と保存に依存している。技術部品の分離だけでは教科横断の学習進行を再利用できたとはいえない。
一方、具体的な第二教科なしに汎用教材schemaを確定すると、英語の暗黙前提を固定する危険がある。

## 決定

- 教科非依存の技術部品、学習進行core候補、教科/問題形式adapter、ホストの組立て/永続化を分ける。
- 今は責任・依存・不変条件・移行条件を文書化する。学習の最終公開契約は英語と第二教科の縦断実証後に確定する。
- 単体ライブラリをFramework依存にしない。Frameworkを使わない一般ツールでも必要な能力だけ利用できる。
- 英語も一つのadapterとする。採点尺度・正規化・教材形式を共通coreへ固定しない。
- 音声入出力、添付原本、egui controlsの限定設計を追加する。その他の候補は着手条件と再検討主体を台帳に残す。
- 通信成功、AI助言、評価の確定、教材登録、保存成功、学習効果を別々に検証する。

## 代替案

| 案 | 採らない理由 / 成立する条件 |
| --- | --- |
| 今すぐ全教科Framework化 | 問題形式・評価基準が未確定。第二教科の実証後なら必要最小のcoreを確定できる |
| 第二製品まで何も決めない | 既存4設計へ英語依存を残し、後の抽出を妨げる。今は境界と禁止依存を記録する価値がある |
| アプリをコピーして教科別に改造 | 短期prototypeには使えても、共通修正・保存整合の継続的な二重管理となる。再利用完成の証拠にしない |
| 多数の小ライブラリを先に公開 | 利用先より抽象化が先行する。具体的な二消費者と互換試験が成立してから配布単位を決める |

## 影響・完了条件

[Framework方針](../reuse/framework.md)に第二教科gate、[候補台帳](../reuse/library-candidates.md)に採否・再開条件を記す。
既存4設計は、教科固有の評価/登録を技術部品へ入れない点を補足する。認証、原本保持、承認、保存失敗、結果不明の安全契約は変更しない。
今回は文書の独立レビューとリンク/構造/非変更確認を完了条件とする。実装・実機・AI品質・二製品運用の確認は後続taskである。
動的plugin、他言語ABI、全OS、共通教材schema、学年体系、一体型アプリか別アプリかは保留する。
判断の再開契機は第二教科/第二利用先の仕様着手、教科分岐のcore混入、保存・認証境界の変更である。
