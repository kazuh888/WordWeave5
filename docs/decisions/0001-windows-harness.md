# 0001: WordWeaveが教材と文脈を所有するWindows Harness

状態：採用。日付：2026-09-17。実装範囲は [UPGRADE-0.4.0.md](../../UPGRADE-0.4.0.md) と [tasks/plan.md](../../tasks/plan.md) による。

## 背景

汎用エディターのエージェント基盤をそのまま移すと、単語学習に不要なツール実行権限や、隠れた履歴への依存が増える。一方、録音・筆跡を教材の根拠にするには、単なるチャット文字列保存では足りない。

比較調査からは、Codex/ACPのプロトコル境界、VS Code/Zedの変更レビュー、DeepSeek Harnessのイベントと永続化の責務分離を採用した。全面プラグイン化やACPへの輸送層交換は行わない。参考設計が持つ全機能の再現ではない。

## 決定

1. WordWeaveが会話・選択文脈・教材・学習記録の正本を持つ。Codexは生成ごとの独立スレッドを使うが、結果の再取得のため非ephemeralとする。永続スレッドを会話の隠れた記憶にしない。
2. 原本を内容ハッシュ付き独立ファイルに保存し、Progressは参照を持つ。SHA-256は破損検査・同一内容の重複排除に使うが、バックアップの代わりではない。原本は自動削除しない。
3. 生成前の実行記録と生成後の本文を保存する。ローカル中断とサーバー中断を区別し、結果不明で再生成しない。再取得にはexact thread/turn IDを必須とする。
4. 教材案は選択往復の固定版と理由・引用を持つ。形式・参照一致・追加/訂正ルールはプログラムで検査する。英語の意味的な正しさは人の確認を残す。AIに教材ファイルの書込権限を渡さない。
5. 教材とProgressの更新は保存意図を先に置く回復可能な2ファイル更新とする。両ファイルの完全同時更新とは称さない。旧版との互換性と障害時の原本保護を優先する。

## 代替案と影響

- Codex側の会話再開を正本にする案：簡単に長期履歴を再利用できるが、利用者が選んだ送信文脈と実文脈がずれるため不採用。
- 全録音・全画像を毎回送る案：文脈量とプライバシー負担が大きく、今回は現在の添付と選択教材根拠に限定。
- APIキーへの音声フォールバック：利用者の認証・課金方針に反するため禁止。能力を確認できなければ機能の制約を表示する。
- SQLiteへの全面移行：保存統合は簡潔になるが、既存データ移行と依存追加の範囲が大きい。現形式を保ち、保存意図と競合検査で限定的に回復する。

原本と実行記録は容量を消費する。自動整理は行わず、明示的な保全手段を提供する。モデルの媒体能力、音声認識品質、実ペン・マイク操作、電源断の全組合せはオフラインテストだけでは検証できない。
